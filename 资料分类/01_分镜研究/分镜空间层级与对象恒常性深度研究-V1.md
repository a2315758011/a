# 分镜空间层级与对象恒常性深度研究 V1

日期：2026-10-22

## 1. 研究目标

解决 AI 从剧本生成分镜/视频提示词时反复出现的“世界状态错误”：
- 书包里的手机为了展示屏幕文字被移到包外；
- 场景已有椅子，人物表演时又生成新椅子；
- 墙面投影变成悬浮空中屏幕；
- 镜中反射变成第二个人；
- 阴影或屏幕内容变成独立实体；
- 道具被遮挡/出画后被当成消失，重新生成时数量漂移；
- 针头、胶带、软管等内部/表面/外露结构混乱；
- 剧本未写鼓掌却自动让所有人鼓掌；
- 一个人的行为被扩展成群体行为；
- 切镜头或相机运动导致世界状态被错误重建。

## 2. 核心研究结论

### 2.1 不能只用自然语言提示词维持世界状态

TSG Bench 对 11 个 LLM 的研究显示：模型在“理解”场景图时表现较好，但在“从叙事生成场景图”时明显更弱，尤其复杂叙事需要隐式拆解为多个动作时，动作分解是主要瓶颈。

结论：主模型不能同时承担“导演创作 + 世界状态数据库 + 物理约束求解器 + 连续性审稿器”。

### 2.2 应采用“叙事层 + 确定性状态层”

2026 年 Agentic Video Generation / GEST 的研究把演员、动作、对象、地点、时空约束表示为正式事件图，并让程序化后端通过工具约束保证规格可执行。论文明确指出：LLM 擅长叙事，但不能可靠追踪 50–200 个事件中的精确状态；单纯分阶段 LLM refinement 甚至 50 次尝试中 0 次得到可执行规格。

适用于本项目的原则：
- LLM：负责剧本理解、导演意图、镜头设计候选。
- SCG/状态后端：负责 entity_id、parent_id、关系、数量、前置条件、效果和时间约束。
- Validator：负责拒绝非法状态转移。
- Renderer Prompt：只能从已经通过验证的状态生成。

### 2.3 场景应当使用层级图而不是平铺文本

3D Dynamic Scene Graph、OpenUSD、Unity Transform 都采用层级关系：
- 节点代表场景、房间、对象、人物、部件。
- 边代表包含、邻接、父子、关系。
- 子对象的位置/状态依赖父对象。

OpenUSD 还提供了特别有价值的思想：
- 场景是分层组成的；
- 各层的“意见”具有强弱顺序；
- 引用资产而不是重复复制资产；
- 实例化与唯一实例是不同概念；
- Relationships 通过稳定的场景路径连接具体对象。

映射到分镜：
L0 原剧本 > L1 场景资产 > L2 空间拓扑 > L3 物体实例 > L4 动作状态 > L5 镜头 > L6 风格。
下层只能覆盖允许覆盖的属性，不能改变高层事实。

### 2.4 对象恒常性必须成为独立验收项

2025–2026 多项视频生成研究把 Object Permanence 单列为世界一致性指标：
- 对象一旦出现，应持续存在，除非合理离场或被遮挡。
- 被遮挡不等于不存在。
- 重新出现时应保持身份与合理位置。
- 无原因出现/消失属于错误。

WROP 进一步表明，即使现代视频模型质量很高，物体在遮挡后消失、从不可能位置重新出现、穿过实体障碍仍是基础性失败。

因此分镜自检必须把以下分开：
existence：是否存在
visibility：是否可见
occlusion：是否被遮挡
in_frame：是否在画框内
identity：是否仍为同一实例
location：世界坐标/父级相对位置

### 2.5 跨镜不能只存上一帧，应维护实体记忆

VideoMemory、Memento、RECAP-Forcing 等近期研究都把长期一致性问题归结为“实体记忆不足”：
- 角色、道具、背景应有显式的语义/视觉记忆；
- 记忆在每镜后更新；
- 再次出现时从实体记忆恢复，而不是由当前提示词重新脑补；
- 长期记忆不能只保存最近帧，还要保存首次出现/身份关键证据。

因此项目应维护 Entity Memory：
entity_id
canonical_asset
first_seen
last_state
identity_features
parent
relations
appearance_changes
last_keyframe
source_ids

### 2.6 多对象交互应该用关系图控制

GraphVid（2026）明确指出：纯文本和轨迹控制很难精确描述多对象交互，尤其遮挡/重叠时；结构化 interaction graph 可以提供更精确的多主体关系控制。

因此“人坐椅子”“手机在书包”“投影在墙上”不能只作为文字短语，而应表示成关系：
(personA, sitting_on, chairA)
(phoneA, inside, bagA)
(projectionA, projected_onto, wallA)

### 2.7 动作必须使用前置条件/效果模型

AI Planning / STRIPS / PDDL 的成熟做法：动作由 parameters、preconditions、effects 定义。

应用示例：
take_out(phoneA, bagA, right_hand)
pre:
- inside(phoneA, bagA)
- open(bagA)
- free(right_hand)
effect:
- not inside(phoneA, bagA)
- held_by(phoneA, right_hand)

sit(personA, chairA)
pre:
- exists(chairA)
- reachable(personA, chairA)
- unoccupied(chairA) 或允许共享
effect:
- sitting_on(personA, chairA)

turn_on_projector(projectorA)
pre:
- exists(projectorA)
- receiver_surface=wallA
effect:
- exists(projectionA)
- projected_onto(projectionA, wallA)

这样可以阻止“直接跳结果”。

## 3. 视觉介质必须类型化

这是墙面投影漂浮问题的根治方法。

至少区分：
1.实体 Object
2.屏幕内容 ScreenContent
3.墙面/幕布投影 SurfaceProjection
4.反射 Reflection
5.阴影 Shadow
6.表面标记 SurfaceMark
7.后期叠加 PostOverlay
8.真正全息/体积视觉 Hologram/Volumetric

规则：
- SurfaceProjection 必须有 projector/source + receiver_surface。
- ScreenContent 必须有 screen_surface。
- Reflection 必须有 reflective_surface + reflected_entity。
- Shadow 必须有 light + caster + receiver_surface。
- SurfaceMark 必须有 carrier_surface。
- 只有 Hologram/Volumetric 可以在剧本明确支持时拥有独立悬浮空间位置。

Unreal/Unity 的 decal/projector 机制也采用“投射方向 + 接收几何表面”的思路，而不是把内容当成空气里的独立平面。

## 4. 影视行业的连续性方法仍然必要

ScreenSkills 对 Script Supervisor 的工作定义包括：
- 开拍前按演员、动作、服装、道具做 continuity breakdown；
- 拍摄时检查对白、动作、视线；
- 对动作、服装、道具以及摄影信息保留详细书面/照片记录。

说明 AI 分镜系统不能只维护“剧情摘要”，而应有类似场记表的逐镜状态记录。

## 5. 推荐系统架构

### Stage A：原剧本事实抽取
只提取明确事实，不做导演创作。
输出 Script Facts。

### Stage B：世界初始化
建立：
- characters
- objects
- surfaces
- containers
- parts
- phenomena
- scene anchors
- relations
- quantity constraints

### Stage C：事件分解
把剧本文字拆成 atomic events。
每个 event 有：
actor
action
target
preconditions
effects
source_id
time constraints

### Stage D：导演层
在不修改世界事实的前提下决定：
景别、构图、镜头运动、切镜、信息披露和节奏。

### Stage E：Constraint Validator
检查：
- ID 唯一性
- parent/child
- contains
- attached
- support/contact
- quantity
- visibility vs existence
- carrier/receiver
- action precondition/effect
- group-action source
- temporal order
- camera/world separation

### Stage F：镜头文本生成
只把已验证的当前状态翻译为人类可读分镜。

### Stage G：下一镜状态提交
只提交当前镜头实际发生的合法状态变化。
未变化项继承。

## 8. 关键测试集

必须至少包含：
- 关闭书包 + 手机亮屏文字不可见。
- 打开书包 + 手机仍在包内。
- 手机完整取出。
- 场景只有椅子A，人物坐椅子A。
- 椅子A移动后位置继承。
- 墙面投影始终贴墙。
- 相机平移但墙面投影不跟相机漂移。
- 关闭投影仪后投影消失。
- 镜中人物不复制。
- 阴影不是实体。
- 针头/胶带/软管内外结构正确。
- 拔针动作到流血有完整因果。
- 剧本未写鼓掌时全场保持中性。
- 一人鼓掌不扩展为所有人。
- 物体完全遮挡后仍存在并在合理位置重现。
- 父容器移动时内部对象随父级移动。
- 已有资产出画后再次出现仍为同一实例。

## 9. 最终判断

当前《剧本转分镜指令 V2.5》和《剧本转分镜自检指令 V2.5》已经具备较完整的文字约束框架，但真正达到批量稳定生产还缺一个“程序化状态后端 + Validator”。

继续只增加自然语言条款的边际收益会快速下降。下一阶段优先级应为：
P0：把 SCG/Entity Memory/Action Preconditions/Effects 变成结构化数据。
P0：实现非法状态转移校验。
P0：建立上述 25 类失败模式的自动回归集。
P1：把分镜正文改成“验证通过状态”的只读渲染结果。
P1：生成后用对象跟踪/关系稳定性再做成片回检。
