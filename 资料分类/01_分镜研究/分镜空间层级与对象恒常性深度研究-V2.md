# 分镜空间层级、对象恒常性与程序化约束深度研究 V2

日期：2026-10-22

## 一、结论先行

当前发现的错误不是若干独立提示词缺陷，而是同一类“世界状态与镜头描述混在一起”的系统问题。

典型表现：
- 手机在书包里，却为了展示屏幕信息被移到包外；
- 场景已经有椅子，表演时重新生成另一把椅子；
- 墙面投影被当成独立矩形道具悬浮到空气中；
- 镜中反射变成第二个人；
- 阴影、屏幕内容、墙上图案脱离载体；
- 道具被遮挡/出画后被当成不存在；
- 针头、胶带、软管的内部/表面/外露结构混淆；
- 剧本未写掌声，却根据“典礼/发言结束”等常识自动让全场鼓掌；
- 一个人的动作被扩大成全体人物动作。

根因：模型在写局部镜头时，同时拥有修改整个世界的自由。

解决方案应从“加强提示词”升级为：
原剧本事实 → 世界状态图 SCG → 原子事件 → 约束校验 → 导演镜头 → 可读分镜正文。

## 二、研究证据

### 1. 场景图：模型擅长读，不等于擅长正确生成
TSG Bench（ACL 2025）评估 11 个 LLM，发现模型理解场景图相对较好，但从复杂叙事生成场景图明显更弱；复杂叙事的离散场景/动作拆解成为瓶颈。

工程含义：
不能让一个长提示词同时承担剧情理解、对象建模、状态更新、导演设计和审核。

### 2. 可执行事件图：LLM 规划与程序状态后端必须分离
Agentic Video Generation（2026）把演员、动作、对象和时空约束表示为正式事件图 GEST。其重要发现是，单靠多轮 LLM refinement 仍不能稳定生成可执行规格；有效架构把自然语言规划交给 LLM，把约束和状态写入程序化后端。

工程含义：
导演 Agent 可以提出镜头方案，但不能直接写最终世界状态；状态变化要经过工具/校验层。

### 3. 多对象交互：结构化关系比纯文本更适合精确控制
GraphVid（ECCV 2026）指出，多对象、遮挡、重叠和接触很难只用文本或轨迹稳定表达，结构化 interaction graph 能更清楚表示对象之间的推、拉、抬、相对运动等关系。

工程含义：
“人坐椅子”“手机在包里”“投影在墙上”要落成关系：
(personA, sitting_on, chairA)
(phoneA, inside, bagA)
(projectionA, projected_onto, wallA)

### 4. 对象恒常性：遮挡不是删除
WROP（2026）专门把 Object Permanence 作为世界模型能力进行训练和考试，并构建大量遮挡/持续存在场景。

工程含义：
必须分开：
- existence：世界里是否存在；
- visibility：当前是否看见；
- occluded：是否被遮挡；
- in_frame：是否在画框内；
- identity：是否还是同一实例；
- location：世界/父级相对位置。

### 5. 长视频一致性：需要实体记忆
VideoMemory（2026）用 Dynamic Memory Bank 保存人物、道具、背景的显式视觉和语义描述，并在每个镜头后更新，以保证跨远距离镜头重现时仍保持身份。

工程含义：
关键实体应维护稳定 entity_id、canonical_asset、parent、relations、last_state、identity_features，而不是再次出现时重新从文字生成。

### 6. 资产实例化：引用资产与重新创造必须区分
OpenUSD 的 Scenegraph Instancing 和 Relationships 把“同一资产的多个实例”“稳定关系目标”“引用/组合”分开管理。共享原型并不意味着实例身份相同；每个实例仍通过场景图路径拥有自己的位置和关系。

工程含义：
- “椅子”是资产类别；
- chairA 是已经存在的具体实例；
- 角色坐下时应引用 chairA；
- 只有剧本明确新增另一把椅子时才创建 chairB。
不能因为需要一个“chair”就重新实例化。

### 7. 图约束验证：审核器不应偷偷修图
W3C SHACL 的基本思想是：
数据图与约束图分离；验证产生报告；验证过程不修改被验证的数据图。

工程含义：
分镜审核器应先报告非法关系/状态，再由修复步骤显式生成新的 SCG 版本；不能“边验证边偷偷修”，否则无法追踪究竟哪一个世界状态通过。

## 三、问题应分成八个大类

### A. 身份与实例
无来源新增、复制、替换、数量漂移、已有资产未复用。

### B. 层级与组成
parent、part_of、container、inside、attached_to、mounted_on。

### C. 接触与支撑
holding、grasping、sitting_on、resting_on、leaning_on、taped_to。

### D. 视觉载体
projected_onto、displayed_on、reflected_in、shadow、surface_mark。

### E. 可见性
存在、入画、遮挡、可读、屏幕朝向、透明/不透明必须分开。

### F. 事件与因果
每个状态变化必须有 precondition → event → effect。

### G. 人物/群体行为来源
actor_id、source_id、trigger_event、authorized_scope 必须存在。

### H. 时间与镜头
相机变化不能改世界；切镜不能删除对象；跨段只能在合法状态点断开。

## 四、层级写入权限

L0 原剧本事实
L1 权威人物/场景/道具资产
L2 场景拓扑、容器和固定锚点
L3 实体实例、部件与关系
L4 事件和状态变化
L5 镜头/摄影机/可见内容
L6 风格、光影、质感

规则：
- L0-L3 是 L4-L6 的上游事实源。
- L5 镜头只能决定“怎么看”，不能决定“世界变成什么”。
- L6 美化不能增加剧情事实。
- 低层冲突时，只能向下修：改构图、景别、调度，不能改容器、父级、资产实例和剧情行为。

## 五、投影问题的正式模型

墙面投影不是 Object，而是 SurfaceProjection。

必须有：
- projection_id
- source_projector
- receiver_surface
- content
- active_state
- projected_onto relation

投影本身不获得自由 floating 世界位置。

合法：
projectorA → projectionP1 → wallW1

非法：
projectorA → projectionP1 → floating_plane_in_air

只有原剧本明确写 hologram/volumetric display 时，才允许空气中独立存在。

相同规则扩展到：
- 手机/电视：ScreenContent
- 镜面：Reflection
- 阴影：Shadow
- 纹身/血迹/字迹：SurfaceMark
- 字幕/UI 后期：PostOverlay

## 六、人物行为来源模型

任何行为：
actor_id + action + source_id + trigger_event

群体行为增加：
actor_ids + scope + authorized_scope

“发言结束”不是“全场鼓掌”的授权来源。
“角色胜利”不是“群众欢呼”的授权来源。
“一人鼓掌”不能自动升级成全体鼓掌。

导演允许添加的只能是不会改变人物立场和剧情含义的最小中性调度。

## 七、动作状态机

以“从包内拿手机”为例：

Preconditions:
inside(phoneA, bagA)
open(bagA)
reachable(handR, phoneA)

Event:
take_out(personA, phoneA, handR)

Effects:
remove inside(phoneA, bagA)
add held_by(phoneA, handR)
set_parent(phoneA, personA)

如果直接从 inside 跳到 held_by，但没有 event，则为非法状态跳变。

吊针同理：
必须区分体内穿刺部分、皮肤表面固定部件、外露连接部件、软管；“暴力拔出→针头离体→伤口/流血”形成可追踪因果链。表面胶带不能被建模成进入皮肤的 part。

## 八、已实现的程序化原型

本轮已经实际创建：
- 分镜SCG数据契约-V1.md
- 分镜SCG校验器-V1.js
- 分镜SCG回归样例-V1.json

实际 Node.js 回归：
- 总案例：12
- 预期不匹配：0
- 结果：12/12 PASS

已经实际验证能拦截：
1. 关闭书包内屏幕文字错误可读；
2. 已有椅子却新增第二把椅子；
3. 墙面投影悬浮/缺接收面；
4. 无来源鼓掌；
5. 局部鼓掌扩大成全场；
6. 胶带被错误放进皮肤内部；
7. 遮挡后道具直接从世界状态删除；
8. 合法手机取出事件不会被误报；
9. 合法椅子复用不会被误报；
10. 合法墙面投影不会被误报。

当前 V1 是核心原型，不是完整物理引擎，尚未自动覆盖全部 E01-E25。

## 九、下一阶段建议

P0：
- 扩充 V2 校验器到完整 E01-E25；
- 增加 canonical_asset 身份替换检查；
- 增加左右手/holder 唯一性；
- 增加 parent 移动时子节点继承；
- 增加数量约束；
- 增加相机状态与世界状态隔离；
- 增加时间区间与动作并行/串行验证。

P0：
把“生成分镜正文”改为 SCG 校验通过后的只读渲染，而不是让正文自己成为事实源。

P1：
将错误规则逐步迁移到声明式约束层。可保持 JSON 数据格式，但借鉴 SHACL 的 shapes/validation-report 思想：约束规则独立、验证输入不可变、结果输出单独报告。

P1：
视频生成后增加视觉回检：对象检测/跟踪、关键资产相似度、投影/屏幕载体关系、数量变化和对象重现身份一致性。

## 十、最终判断

最可靠的方向不是继续把提示词写到越来越长，而是把“导演创造力”和“世界物理/连续性权限”分开。

AI 可以决定：
- 镜头怎么拍；
- 信息何时揭示；
- 景别和节奏如何组织。

AI 不可以未经授权决定：
- 手机从包里出来；
- 新增第二把椅子；
- 投影离开墙面；
- 镜像变真人；
- 被遮挡道具消失；
- 谁鼓掌、谁欢呼；
- 哪个表面部件进入身体；
- 任何没有 event/source_id 的世界状态变化。

因此最终生产体系应是：
剧本 → Script Facts → SCG → Event State Machine → Validator → Director → Storyboard → 独立复核 → 视频生成 → 视觉回检。
