## 已核实的事实
- 网关原始母素材任务 jobId=8c2eb70a-9af6-4956-8574-20ea83ceecae；状态 completed，原始 PNG 2048×2048。
- 使用批量美术计划中的 prompt 加固定后缀重新计算 SHA-256，结果与账本 promptSHA256=0e5b4d48b1b4d6c9159dbd028f9ce49a79f0878697cd68cb825a24a4bc6649ee 一致。
- 该请求明确写着 Image is ONLY an individual master sprite，属于单个兽人母图生产；不是动作分帧请求。响应摘要显示 referenceCount=0。
- 图像加工脚本对行走只做整图平移/亮度调整，对攻击只做整图位移及简单多边形，对死亡和水晶破碎只做缩小/淡出。因此不可能形成合格的逐肢体挥击、交替迈步或碎块破裂。
- 现有动画候选验收-v0.5.json 明确给出 CANDIDATE_NOT_FINAL，相关动作 semanticReview 与 engineImport 仍为 PENDING。不能因已有 8 帧/独立文件/像素不同判 PASS。
- 名为“正式资产”的既有目录中有不合格的早期候选帧；必须阻止直接发布，不能删除或覆盖以免破坏其他 Agent 正在使用的工程。找到本地“兽人首领.zip”含24个 PNG，但不能仅凭此认定它与聊天中的“兽人首领(1).zip”逐字节一致。
- 原动画加工脚本曾存在将一个文件的哈希与自身比较的无效覆盖检查，且曾写入正式资产目录；现已改为候选目录路径与同名内容不可变校验。
- 当前加工脚本还具有语义 fail-closed 入口，检测到走路/攻击/死亡/破碎等需要真实姿态的动作即返回 FAIL_ANIMATION_SEMANTICS（退出码2），故当前不会再次生成假合格帧。此状态为阻断，不是制作出正确动画。

## 修复剩余条件（缺一不可）
1. 给角色母图建立真实关键姿态和武器/肢体轨迹的审定合同：兽人锤击必须有起手、蓄力、挥动、命中、收招；行走需左右腿切换；死亡需明确失衡/倒地；水晶碎片必须从主体分离。
2. 确认 Provider 是否支持结构化参考图 / 固定视角 / 多帧格，提交前以请求快照保留完整文本、参考图 SHA、模型/账号、幂等 ID；已提交任务只能按旧 jobId 恢复，不重新发送。
3. 对返回图片先分类为单母图 / 标准帧图集 / 非规则拼贴，再选择裁切；禁止把整图按固定 4x2 生切。
4. 以实际 GIF 播放和 Cocos Creator 场景动画审核动作语义、锚点、事件，并保留引擎实际运行证据；未获得审查 PASS 不允许自动进入正式资源或项目 manifest。
5. 失败只返工失败的动作，保留原始文件和任务证据；不得把差异帧数或图集排版当作质量证明。
