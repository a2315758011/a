# AI编剧状态账本与续写门禁 V1.0

日期：2026-10-26

## 一、目标

把 State Retention 从“创作原则”变成 AI 可执行的生成协议。

核心要求：

> **AI不是每次根据最近几千字重新猜人物是谁，而是必须读取一个显式、可更新、可验证的叙事状态。**

生成下一场/下一集之前，先验证：
- 事实还成立吗？
- 人物知道什么？
- 人物已经学会什么？
- 关系现在是什么状态？
- 哪些边界已经建立？
- 哪些承诺已经作出？
- 哪些资源已经获得/失去？
- 哪些人物弧线已经完成，不能原样重开？

---

# 二、状态账本结构

每个项目至少维护7张表。

## 1. WORLD_STATE｜世界事实

记录不可随意变化的客观事实：

- 时间
- 地点
- 人物生死
- 亲属关系
- 职业
- 财产
- 法律状态
- 世界规则
- 已公开秘密
- 已锁定历史事件

字段：

- state_id
- fact
- established_at
- source_scene
- confidence
- mutable
- allowed_transition
- current_value

---

## 2. CHARACTER_KNOWLEDGE｜人物知识

必须区分：

> **作者知道 ≠ 观众知道 ≠ 角色知道。**

每个角色单独维护：

- know_fact_id
- knows = true/false/partial
- learned_at
- evidence
- can_forget = false
- misunderstanding
- corrected_at

禁止：
角色使用自己从未获得的信息。

---

## 3. CHARACTER_STATE｜人物能力与身份

字段：

- character_id
- competence
- self_belief
- fear
- desire
- shame
- defense
- value_conflict
- current_identity
- completed_learning
- unresolved_learning

特别记录：

### completed_learning
角色已经真正学会的东西。

例如：
“不能靠不断救别人证明自己的价值。”

这不是一句台词，
而是之后剧情必须尊重的已建立状态。

---

## 4. BOUNDARY_STATE｜边界与责任

字段：

- owner
- counterpart
- boundary
- established_at
- tested_at
- current_strength
- relapse_conditions
- reset_forbidden

示例：

女主—母亲：
“愿意陪护每周2天，但不承担全天照护。”

后续母亲再次要求全天陪护时，
AI必须明确判断：

A 保留边界  
B 有因果复发  
C 新条件导致重谈  
D 无解释重置

D禁止。

---

## 5. RELATIONSHIP_STATE｜关系状态

不要只写：

“他们感情变好了。”

要记录可验证状态：

- trust_level
- intimacy
- power_balance
- obligation
- unresolved_conflict
- explicit_commitment
- hidden_information
- current_distance

例如：

第18集丈夫明确把工资卡交回夫妻共同管理。

则：
“财务权力重新分配”
必须成为后续关系状态的一部分。

---

## 6. ARC_STATE｜人物弧线状态

每条核心弧线维护：

- arc_id
- initial_false_belief
- wound
- current_stage
- completed_turns
- pending_turns
- irreversible_changes
- forbidden_repetition

典型阶段：

0 未觉察  
1 触发  
2 否认  
3 初步行动  
4 旧系统反弹  
5 复发  
6 整合  
7 稳定新状态

禁止：
已经到6/7的角色，
无解释回到0/1重新走一遍。

---

## 7. COMMITMENT_LEDGER｜叙事承诺

记录故事已经向观众做出的承诺：

- 某秘密一定会解释
- 某关系冲突必须解决
- 某道具将发挥作用
- 某人物的目标必须被回应
- 某伏笔已经建立

字段：

- commitment_id
- created_at
- expected_payoff_window
- status
- payoff_scene
- abandoned_reason

这防止：
钩子不断产生，但故事忘记还债。

# 三、生成下一集之前的五道门

## Gate 1｜Fact Gate
新剧情是否违反已锁定世界事实？

若是：
阻止生成。

---

## Gate 2｜Knowledge Gate
角色是否使用自己不可能知道的信息？

若是：
阻止生成。

---

## Gate 3｜State Gate
角色行为是否违背已经形成的能力、身份、边界？

若违背，必须分类：

### A Relapse
旧模式复发。
允许，但必须存在新压力、角色自知和后续整合。

### B Revision
新信息使角色改变判断。
允许。

### C Strategy
角色明知真实状态，但有意识伪装/妥协。
允许。

### D Reset
文本无解释让人物退回旧状态。
禁止。

---

## Gate 4｜Arc Gate
新冲突是不是在让人物重复学习已经完成的同一课题？

如果是：
检查是否存在新的更深层问题。

没有：
禁止。

---

## Gate 5｜Commitment Gate
这一集是否：
- 新增大量悬念
- 却没有偿还任何旧承诺？

若连续发生：
触发 Reward Debt / Commitment Debt 警告。

---

# 四、场景级 Transition Contract

生成场景之前必须明确：

## Before State
场景开始前：
人物和关系是什么状态？

## Trigger
什么事件打破当前稳定？

## Allowed Transition
本场允许哪些变化？

## Forbidden Transition
哪些变化违反前文？

## After State
场景结束后：
至少一个状态是否真实改变？

如果场景结束后：

WORLD、KNOWLEDGE、CHARACTER、BOUNDARY、RELATIONSHIP、ARC、COMMITMENT
全部没有变化，

则检查：
该场是不是纯装饰/重复。

---

# 五、状态改变必须有证据

AI不得写：

“她成长了很多。”

必须写成：

- 她做出了以前不会做的选择；
- 她承受了以前会躲开的代价；
- 她没有撤回新的边界；
- 她主动承担自己选择的后果；
- 关系中的资源/责任发生可观察变化。

原则：

# Change Must Leave Evidence.

---

# 六、AI续写审查输出格式

每次生成前，审查器先输出内部结构：

STATUS CHECK

1. 世界事实冲突：
PASS / FAIL

2. 人物知识冲突：
PASS / FAIL

3. 状态连续性：
PASS / RELAPSE / REVISION / STRATEGY / RESET

4. 弧线重复：
PASS / WARNING / FAIL

5. 未偿承诺：
数量 + 最老承诺年龄

6. 当前Global Reward Gap：
N集

7. 本集至少推进：
C1 / C2 / C3 / C4 / C5 中哪一项

若出现FAIL：
不得直接生成正文。

先执行局部修复。

---

# 七、局部修复优先于全文重写

如果发现冲突：

错误策略：
重新生成整集。

正确策略：
定位最小冲突片段。

修复顺序：

1. 找到冲突状态ID；
2. 找到前文建立证据；
3. 判断新剧情是否必须保留；
4. 如果必须：
   添加合理桥梁；
5. 如果不必须：
   删除/替换冲突行为；
6. 更新状态账本；
7. 再生成后续。

这样避免：
修一个bug，制造三个新bug。

# 九、AI编剧真正需要的不是“大上下文”

大上下文有帮助，
但不能替代结构化状态。

原因：

长篇文本里真正需要被强约束的是：

- 哪些事实已锁定；
- 哪些变化已经不可逆；
- 哪些关系已经进入新阶段；
- 哪些人生课题已经完成；
- 哪些承诺尚未兑现。

所以：

# Context ≠ State.

上下文是历史。
状态是“历史发生以后，现在世界变成了什么”。

# 十、与本研究的连接

这套状态账本同时保护：

1. State Retention
2. Reward Retention
3. Arc Continuity
4. Narrative Commitment
5. Reward Density

最终让AI写作从：

“根据上一集继续编”

变成：

> **在当前合法状态中，生成下一次有意义的状态转移。**
