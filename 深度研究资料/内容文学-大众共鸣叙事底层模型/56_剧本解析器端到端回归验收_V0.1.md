# 二、首次运行发现的真实缺陷

## BUG-01 Markdown集标题

输入：
# 第2集：两天就是两天

旧解析器没有识别Markdown前缀“#”，
导致：
- episode错误保持1；
- 标题被当成普通动作行。

修复：
EP_RE允许1—6级Markdown标题前缀。

---

## BUG-02 假场景

因为BUG-01，
第一个“场景1”出现时，
前面的错误标题已经被写进current_scene，
于是被flush成一个不存在的场景。

表现：
预期3场，
实际4场。

BUG-01修复后：
恢复为3场。

---

## BUG-03 动作行被识别成角色

输入：

母亲给林晚发来一条语音：“医药费你弟弟最近手头紧，你先垫一下吧。”

旧DIALOGUE_RE允许20字符speaker，
因此把：

“母亲给林晚发来一条语音”

误识别成角色名。

修复：
参考解析器将直接“角色：台词”speaker长度收紧到8字符。

说明：
这只是规则型解析器的保守策略，不适合替代LLM语义解析；
但能显著降低中文动作行冒号造成的假角色。

# 四、最重要的门禁测试

解析器compile阶段会产生：

review_required=true

原因：

自动抽取只能提出：
- Boundary候选
- Knowledge候选
- Reward候选
- Commitment候选

不能自行裁决其是否应成为Canon。

首次端到端连接时发现：
旧Auditor没有强制阻止未审查候选。

这存在：
Parser Draft误Commit到Canon
的潜在风险。

---

# 五、修复：R000 Unreviewed Candidate

新增硬规则：

任何：

- Delta Change
- Reward
- Opened Commitment
- Scene Contract

只要：

review_required == true

则：

VERDICT = BLOCK

RULE = R000

必须经过语义审查后，
才能改为正式状态变化。

# 七、这条门禁为什么重要

如果没有R000：

关键词解析器看到：

“我就知道，女儿嫁出去以后心就不在家了。”

可能提取成Knowledge候选。

但这句话只是母亲的主观判断，
不应自动成为：

WORLD FACT：
女儿心不在家。

所以：

# Extraction ≠ Truth.

自动解析的职责是：

“这里可能发生了一个重要状态变化。”

语义审查器的职责才是：

“它究竟属于事实、人物信念、误解、情绪台词，还是根本不该入账。”
