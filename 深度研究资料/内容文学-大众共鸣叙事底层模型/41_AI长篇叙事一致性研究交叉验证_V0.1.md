# 六、Dual Memory：进展与可行性要分开

2026 EMNLP Findings：
Aligning Progress and Feasibility

提出双记忆：
- Progress Memory：负责总体目标有没有前进
- Feasibility Memory：负责当前转移是否合法

来源：
https://aclanthology.org/2026.findings-emnlp.227/

虽然研究对象不是小说创作，
但它提供了一个很有价值的架构启发：

## AI编剧也应该拆成两套检查

### Progress
这一集有没有让：
- 人物弧线
- 关系
- 悬念
- 主题
真正向前？

### Feasibility
这个变化是否：
- 符合事实
- 符合人物已有状态
- 符合世界规则
- 符合角色知识

这两件事不能用一个“总体评分”代替。

# 七、本项目应该采用的最终架构

## Layer 1 Static Bible
静态故事圣经：
- 世界规则
- 人设初始值
- 核心主题
- 禁止项

## Layer 2 Dynamic State Ledger
每一集后更新：
- 人物状态
- 关系
- 边界
- 知识
- 资源
- 已完成弧线

## Layer 3 Commitment Ledger
记录：
- 未兑现伏笔
- 承诺
- 悬念
- 必须回答的问题

## Layer 4 Transition Validator
生成下一场之前检查：
- 是否允许这个状态变化

## Layer 5 Reward Validator
检查：
- 这一场有没有真实变化
- 是否出现Global Reward Gap
- 是否撤销已有回报

## Layer 6 Local Repair
只修错误转移，
不无脑全篇重写。

# 八、最重要的新设计原则

## 1. 自然语言摘要不是唯一事实源

摘要容易：
- 漏细节
- 模糊状态
- 把“曾经”压成“现在”
- 丢失谁知道什么

状态必须结构化。

---

## 2. 状态更新必须是增量的

每生成一场：

Before State  
→ Event  
→ Transition  
→ After State

只更新真的变化。

---

## 3. 不可逆变化必须单独标记

例如：
- 某角色死亡
- 某身份公开
- 某关系彻底决裂
- 某秘密已被某人知道
- 某人物弧线完成

这些都不能仅靠“最近上下文”记忆。

---

## 4. 生成与审查不能是同一步

至少逻辑上分成：

Writer
→ State Checker
→ Reward Checker
→ Repair

避免模型一边发明事实，一边自己批准事实。

---

# 九、当前研究边界

这些论文主要证明：

> 结构化状态与验证机制能改善长篇一致性。

它们并不能直接证明：

- 本项目七层状态分类就是最优；
- SRR能预测商业成功；
- Reward Density一定提高留存；
- 叙事后遗层一定比传统爽剧赚钱。

因此：

技术一致性证据
与
内容商业价值证据

必须继续分开。

# 十、对用户当前AI创作系统的直接意义

未来无论是：
- 短剧
- 漫剧
- 小说
- 分镜脚本
- 多Agent编剧

都不应该让每个Agent仅凭完整历史文本自由续写。

正确方式更接近：

> **共享同一套结构化状态账本，所有Agent只能提出合法状态转移，审查器先验收再写入新的状态。**

这样才能真正减少：
- 人设漂移
- 忘设定
- 复活死人
- 重复成长
- 关系反复横跳
- 伏笔失踪
- 为了新冲突强行降智
