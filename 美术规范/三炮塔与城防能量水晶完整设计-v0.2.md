## 1. 设计修复结论
**被保护物：城防能量水晶（objective_energy_core）**，它是固定在城墙后方主基地里的大型能量核心。它不攻击、不属于三种随机炮塔、不分配观众、不接受“送礼让自己的炮塔升级”的指令。它有公共生命值与损毁动画，全直播间所有参与观众共同守护它。

**第三炮塔修正：原“霜晶减速塔”改名“寒霜喷射塔”**，技术稳定ID `tower_frost` **保留**，防止以后接入旧ID时指向错误逻辑。主体必须是矮胖机械喷嘴+冷凝管/线圈+金属底架，可以发射青蓝冰雾，但**禁止竖立晶体、宝石尖塔、大块水晶剪影**。大型晶体造型只能属于城防能量水晶。

两者从外观、ID、功能、地图层和升级规则上彻底分离。

### 关键信息优先级
1. 镜头内**始终看得见被保护水晶或它的位置提示**，敌人前进方向要朝向它。
2. 顶部始终有清晰的“城防核心生命值”，受击闪红/掉血；0时主水晶破碎并进入失败。
3. 多人昵称只标注在个人炮塔，不压到水晶与共同生命值；礼物升级反馈只作用于用户本人炮塔。
4. 入侵路线、城门/城墙和地板由场景图层控制；不得把地面烘焙进任意炮塔、水晶或机械底座素材。

## 4. 主水晶美术规格（候选）
| 内容 | 源文件与制作标准 | 游戏显示目标 |
|---|---|---|
| 主晶体 `核心主体` | 384×384 RGBA逐帧PNG；主体非透明区另测 | 可见高度初定140–190屏幕px，在1080竖屏设计视口 |
| 石金属支架 `核心基座` | 256×256 RGBA独立层，固定碰撞/占地以关卡逻辑定义 | 与核心同一世界挂点，关闭基座仍能单独显示水晶 |
| 轻伤/重伤裂纹 | 独立RGBA覆盖，分别控制阶段 | 血量明显变化，不能靠UI条单独传达 |
| 受击闪烁 | 6帧@10fps，短时播放一次 | 不让画面整个闪白 |
| 正常循环 | 8帧@8fps（晶体内能量流动） | 一眼能辨，动画不是复制同一PNG |
| 破碎/失败 | 12帧@12fps | 破碎后明确提示失败/结算 |
| 核心血条 | Cocos UI / 文字图层，**绝不画进PNG** | 始终可见 |

核心基座允许石头或金属支架，但**不允许携带成片草地、地图地砖、背景天空或者预览底板**。和其他角色一样需要真实Alpha、无绿边、锚点和两种不同地表运行检查。

主晶体不可跟着观众进入/退出而产生或消失；它属于本局共享建筑。塔位可挤占路两侧，但不能覆盖核心。

## 5. 三款炮塔的资源、尺寸与Lv1-Lv5原则
- 第一版塔体透明画布256×256；主水晶透明画布384×384（不同尺寸因为在局内承担的视线焦点不同）；底座独立，昵称与等级独立UI。固定同塔各等级落地锚点，不允许缩放造成基线跳动。
- `tower_repeater`连珠速射：双枪管→护板→散热槽→弹匣→精英装甲。
- `tower_mortar`熔芯重炮：粗炮口→加压条→宽炮口→炮盾→高能护甲。
- `tower_frost`寒霜喷射：单/双冷媒喷口→加护板→双冷凝筒→强化线圈→重型喷口。**每一级仍是机械喷射器，不变成水晶塔。**
- `objective_energy_core`城防主水晶按**血量/受击状态**切换，并不是随着观众礼物升级；不计入3×5=15套炮塔形态。
- 塔升级仍旧沿用Lv1到Lv5的**候选**预算，最终数值待G0/G1实际验证，不得把未确认等级上限伪装成官方事实。

## 6. 防守机制示例（非正式数值）
- 敌人从画面上方/外缘出现，沿验证过的路径抵达城防主水晶攻击范围；只有**真实触发攻击事件**时按规则扣核心血，而不是一刷出就扣。
- `CoreHP = max(0, CoreHP - validHitDamage)`；建议试算最大HP100、普通怪一击10、Boss一击30。**全部都是原型候选参数**。
- 核心HP>0时守住全部波次判胜利；HP=0判失败、播放核心破碎、进入失败结算。受击动画不可重复触发扣血，伤害计算由规则系统控制。
- 怪物先攻击城墙还是直冲核心、怪物绕行和城墙是否有独立耐久，待实际对标和G0玩法核实；首版默认城墙是背景防线与路径结构，**胜负核心只有主水晶血量**。
- 不能让水晶兼任攻击炮塔、敌人出生点和结算物品。
