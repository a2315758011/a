# 工程任务观察站｜中文维护手册

> 当前版本：云端监控开发原型。代码已保存到 GitHub 隔离开发分支，**尚未上线正式的云端实时服务**。
>
> 当前任务数据是模拟样例，不是你电脑正在执行的真实项目。正式接入前，绝不把模拟进度当成实际进度。

## 一、你可以用它看什么

打开看板后，主要看四块信息：

| 位置 | 作用 |
| --- | --- |
| 已登记任务 | 一共需要完成多少项工作 |
| 已验收任务 | 真正通过测试的任务有多少 |
| 验收覆盖率 | 有证据的已完成任务比例，不是 AI 随口猜的进度 |
| 故障与受影响节点 | 哪一步报错、以及它影响了后面哪些工作 |

中间的任务依赖图使用颜色区分状态：

- **金色**：已经通过测试验收。
- **蓝色流动线**：正在处理的任务。
- **红色**：任务失败，或者被前面的失败任务影响。
- **黄色**：任务正在等待前面的任务完成。

点击任务方框，可以在详情中看到负责人、上一次成功执行的步骤、故障根因、下一步恢复位置和验收依据。

## 二、网页崩溃后怎么恢复

1. 重新打开监控页面。
2. 找到上次执行的项目和任务。
3. 查看该任务的**最后成功步骤**和**下一步恢复位置**。
4. 如果页面显示“采集数据过期 / 本地可能失联”，代表云端没有收到新消息。此时只能看最后一次真实记录，不能误认为任务仍在执行。
5. 恢复电脑或者 AI 连接后，同一个任务应当继续写入记录，不重新计算已通过的测试。

**注意**：上述完整恢复流程是正式版的验收目标，目前 GitHub 页面仅提供模拟数据演示，尚未打通实际采集和云端存储。

## 三、日常维护，你只需要记住这些

| 常见情况 | 应该怎么理解 |
| --- | --- |
| 网页打不开 | 先看部署地址是否有效，当前版尚未发布正式地址 |
| 页面显示“演示数据” | 不是你的真实任务，不代表已经开始执行 |
| 一直显示“数据过期” | 上游数据没有更新，检查采集器、电脑和云端接收服务 |
| 红色任务越来越多 | 点击最上游红色节点，找第一个实际失败的根因 |
| 百分比不动 | 没有新增“通过验收”的任务，不代表一定卡住 |
| 任务显示英文编号 | 编号用于跨系统定位，状态和说明都应显示中文 |
| 本地 MCP 断开 | 云端应保留最后已知状态，重新连接后补发丢失期间的事件（待实现） |

## 四、文件说明

| 文件 | 用途 | 你需要修改吗 |
| --- | --- | --- |
| `index.html` | 网页界面与任务流程图 | 通常不需要，由 AI 维护 |
| `snapshot.json` | **模拟数据**，用于演示网页 | 不要把它当真实进度 |
| `README.md` | 当前中文操作与维护手册 | 需要时让 AI 更新即可 |

代码中可能出现英文技术字段，这是程序对接使用的固定名称；**所有面向你的状态和操作说明必须显示中文**。修改英文技术字段可能导致原有系统无法识别，所以不直接翻译底层接口。

## 五、准备中的云端正式版

系统将分为三个部分：

1. **云端可视化网页**：不同电脑或手机都能查看任务树、执行记录、进度和恢复点。
2. **云端记录服务**：保存任务状态、错误、事件和最后心跳，不依赖聊天网页保持打开。
3. **本地任务采集器**：从现有工程管理器读取真实状态，联网时上报，断网后排队补发。

正式版必须通过登录鉴权，不能把个人工程日志和任务恢复信息直接暴露在公开 GitHub 仓库里。
