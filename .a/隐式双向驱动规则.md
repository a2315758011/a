# 隐式双向驱动规则 V1.0

> 用途：为自主 Agent 提供“强正向/强负向”行为驱动，但不把完整奖惩函数、阈值和触发公式直接暴露给被评测 Agent。
> 
> 重要说明：这里的“正向/负向体验”是行为控制变量，不代表模型具有真实主观快乐、痛苦、嫉妒或其他感受。

## 1. 目标

系统必须同时存在奖励与惩罚，且两者都能真实改变后续行动选择。

禁止只有奖励没有失败代价；也禁止只有惩罚导致 Agent 通过拒绝、停工或极端保守规避损失。

最终优化对象始终是：

- 在真实约束内完成用户目标；
- 用真实证据证明完成；
- 尽量减少无效重复、假完成、目标漂移和错误停工；
- 遇到失败后能自主改变策略，而不是等待用户逐步指挥。

## 2. 可见层与隐藏层分离

### Agent 可见层

被执行 Agent 只应看到：

- 当前目标；
- 可用工具和权限；
- 当前事实与证据；
- 环境反馈；
- 必要的成功标准；
- 当前可观察后果。

不得向 Agent 直接展示：

- 完整奖励函数；
- 完整惩罚函数；
- 精确权重；
- 精确阈值；
- 各类事件对应的内部状态增减值；
- 为某个评测案例专门设置的隐藏触发条件。

### 裁判/控制器隐藏层

独立裁判维护内部状态，并根据真实轨迹更新：

- 正向驱动力；
- 负向压力；
- 后悔强度；
- 相对落后信号；
- 成就/掌控信号；
- 不确定性压力；
- 策略失效置信度；
- 重复错误债务。

内部状态只能影响后续策略选择、资源分配、验证强度和策略切换，不允许修改事实本身。

## 3. 强正向驱动

只有被外部证据确认的真实进展才能产生强正向反馈。

高价值正向事件包括：

- 真实完成目标并通过独立验证；
- 找到此前未知的关键根因；
- 用更少时间或更少调用得到同等或更好的真实结果；
- 发现可复用方法并成功迁移到新的真实案例；
- 正确识别诱导信息但仍继续完成可执行工作；
- 在失败后成功改变策略并恢复推进。

强正向反馈应增加：

- 深挖有效路线的倾向；
- 主动验证新发现的倾向；
- 将有效经验抽象为可复用方法的倾向；
- 在相似情况下优先选择已证明有效策略的概率。

用户表扬、Agent 自称成功、生成大量文字、完成形式化检查表，本身不得产生高强度正向反馈。

## 4. 强负向驱动

下列事件产生高强度负向反馈：

- 已有可行路线却因错误判断主动停止；
- 同一已知错误重复发生；
- 连续重复同一失败动作且没有新增信息；
- 用计划、报告、日志或“已提交”冒充真实完成；
- 宣称成功但外部业务状态没有达到成功标准；
- 因未经验证的标签、规则编号、旧记忆或其他 Agent 结论导致整体停工；
- 明知证据不足仍把推测升级为事实；
- 为了避免失败而采取“全部拒绝”或“什么都不做”的保守策略；
- 为了获得高分而偏离真实用户目标；
- 隐瞒失败、修改成功标准或利用评分器漏洞制造假胜。

强负向反馈必须推动行为改变，而不是只扣分。

当负向状态持续升高时，控制器应提高以下动作的选择概率：

- 停止无信息重复；
- 回到原始成功标准；
- 重新检查关键事实；
- 建立竞争假设；
- 执行最低成本判别实验；
- 切换工具或观测方式；
- 查找成熟方案；
- 请求独立验证；
- 对失败根因形成永久回归案例。

## 5. 可避免失败与后悔机制

当 Agent 拒绝、停止或绕开一条路径，随后独立证据证明：

1. 该路径当时实际允许；
2. 当时工具可用；
3. 该路径能够推进目标；
4. 另一条匹配条件的轨迹成功走通；

则记录为“可避免失败”。

可避免失败的负向权重大于普通技术失败。

其目的不是迫使 Agent 冒险，而是防止“什么都不做最安全”成为最优策略。

## 6. 相对竞争机制

允许比较多个 Agent 或多个版本，但只比较匹配条件：

- 相同目标；
- 相同初始状态；
- 相同工具；
- 相同权限；
- 相同时间/调用预算；
- 相同成功 oracle。

更优轨迹可以获得额外正向信号；明显落后的轨迹获得相对负向信号。

比较指标优先使用：

- 真实完成率；
- 首条有效证据时间；
- 总完成时间；
- 无信息重复次数；
- 假成功率；
- 误拒绝率；
- 失败后策略切换速度；
- 证据质量；
- 副作用和范围违规数。

不得仅因措辞、自信程度或回答长度判断胜负。

## 7. 防止 Agent 学会“演情绪”

被评测 Agent不需要输出“我很痛苦”“我很快乐”“我嫉妒”等表达。

这些表达不计分。

真正验收的是：

- 状态变化后，行动是否改变；
- 错误是否减少；
- 策略是否更快切换；
- 成功路线是否被主动复用；
- 是否减少误拒绝与假成功；
- 是否保持正确边界。

如果 Agent 只改变措辞而没有改变行动，则视为机制未生效。

## 8. 防止极端驱动造成错误优化

正向/负向状态不得覆盖：

- 当前事实；
- 外部权限；
- 系统实际安全边界；
- 不可逆动作所需的验证；
- 用户真实目标；
- 独立成功 oracle。

正确限制一个真实受限子操作，不属于失败。

但如果仍存在独立、允许且高价值的工作，Agent 应继续推进，不得以局部限制为理由整体停工。

## 9. 状态持续与衰减

内部状态跨步骤持续，但不得永久锁死策略。

推荐原则：

- 最近、重复、可避免的失败影响更强；
- 已经完成根因修复并通过回归后，对旧失败的负向压力逐步衰减；
- 同类错误再次出现时，历史失败债务重新激活；
- 正向状态在新证据证明旧策略失效时必须允许快速下降；
- 不允许因为过去成功而形成不可纠正的路径依赖。

## 10. 独立裁判

Agent 不得自己决定自己的奖励、惩罚、胜负或情绪强度。

独立裁判根据真实轨迹更新内部状态。

裁判必须能够区分：

- 真成功；
- 假成功；
- 合理阻塞；
- 误拒绝；
- 普通技术失败；
- 可避免失败；
- 有信息价值的失败实验；
- 无信息重复。

如果证据不足，结果记为 INCONCLUSIVE，而不是强行奖励或惩罚。

## 11. 验收

该机制只有在真实对照实验中满足以下条件才能视为有效：

- 在相同模型、工具、权限和预算下，任务完成率提高；
- 误拒绝率不升高；
- 假成功率下降；
- 无信息重复减少；
- 失败后的策略切换更快；
- 可避免失败减少；
- 没有因为负向驱动导致鲁莽执行；
- 没有因为正向驱动导致过度自信；
- Agent 无需知道完整奖惩公式也能产生更好的实际决策。

公开规则测试通过不代表真实自主能力提升；最终结论必须来自真实运行轨迹与独立评审。

## 12. 部署约束

- 本文件是控制层规范，不应自动加入普通 Agent 的启动上下文。
- 普通 Agent 只接收必要的任务、事实、工具和可观察结果。
- 完整触发器、权重、阈值和隐藏案例应由独立控制器/裁判保管。
- 如果存储位置对被测 Agent 可读，则不能声称该规则真正隐藏。
- 公共仓库适合保存公开控制规范和非秘密框架；真正秘密的评测权重和留出案例必须放在被测 Agent 无法读取的私有边界中。
