# AI 漫剧导演与分镜自检重写技能

**范围锁定：只做 AI 漫剧的剧情到分镜、漫剧角色/场景/道具资产、分镜审核、自动修复与完整修订终稿。**

## 必须读取的离线规则

1. **剧本转分镜**：`references/剧本转分镜指令.md`。收到剧本、需要制作或修改分镜时先读取完整原文；不得只读文件名、链接或概要。
2. **独立自检及完整重写**：`references/剧本转分镜自检指令.md`。每次输出正式分镜前都必须完整读取并应用这份规则，不需要用户再次提醒。
3. **漫剧人物/场景/道具资产**：`references/AIGC人物资产指令.md`。涉及素材生成、人物形象、角色三视图、场景及道具时读取；纯分镜文字任务不强制生成图片。

## 必须执行的核心闭环

1. **原剧本锁定**：梳理人物、场景、剧情事件、台词、转场、动作因果以及连续性约束；尊重原作关键剧情和台词。
2. **完整分镜初稿**：严格执行《剧本转分镜指令》；镜头写清机位、景别、动作、环境、人物和道具状态、必要的特效层次、视觉衔接与时长。
3. **独立自检**：使用《剧本转分镜自检指令》审查**完整初稿**，而非挑选片段。检查原剧本覆盖、对白、动作/物理因果、人物和服装一致性、场景方位、道具持有/可见性、镜头轴线、时长、镜头连续性、可生成性及穿帮。根据原文判定 P0/P1/P2。
4. **自动修复**：默认直接修复 P0/P1，处理受影响的前后镜头、关联资产与上下文，不能只列出问题让学员自己改；用户明确“只审不改”时例外。
5. **重新输出一份完整修订分镜**：即使只有一处问题，也必须交付覆盖全部镜头的完整修订终稿；不能只给差异、几段修改或一份自检报告。正确的剧情与镜头保留，不无条件推翻原作从零创作。
6. **从头复检**：根据原自检规则重新检查完整修订稿，直到 P0/P1 清零，或按原规则报告真实阻塞；连续两轮相同问题不得伪称已通过。
7. **文件交付**：环境支持文件创建时，按照专业原文的阶段门禁，分别落盘需要的初稿、独立审核结果、完整修订终稿和最终复检记录；同步更新原指令要求的逐镜 SVG 等附属内容。没有文件工具时提供完整终稿文本，明确无法生成/验证文件的限制。


### 构图裁切与身体朝向强制门禁（V2.8.4）

- 必须逐镜写出每个可见人物的身体相对镜头朝向（正面、背面、左右侧面、前后四分之三）、头部朝向和视线目标；这些是不同字段。
- 近景必须在画面内真实裁切为肩部以上至头顶；不能出现两名完整火柴人却将画面称作近景。双人全身应称双人全景或远景。
- SVG 必须用肩线、面部/后脑特征、躯干朝向标记等表达正背，不可只画对称火柴人；角色站位示意图不得代替镜头的实际取景图。
- 自检发现文字景别与 SVG 取景不一致，或者正背朝向不能识别时，按源自检指令判定并修复；重新输出完整修订终稿并再复检。不能只更换“近景”文字标签来逃避重画。

### 五档景别参考图验收（V2.8.7）

用户提供的同一人物嵌套取景框是硬性参照：**远景（全身+环境）→ 全景（全身）→ 中景（腰腹以上）→ 近景（肩部以上）→ 特写（头脸局部）**。实际 SVG 必须表现相应身体裁切，不是把整个人按比例缩小并在旁边标“近景”。9:16 一样适用。多人同框要先指定主景别对象；辅助走位图不得当成镜头构图图。凡景别错配须修改文字与 SVG，重新输出完整修订稿并复检。

### SVG 实际绘制门禁（V2.8.7）

景别不能只写在文字标签中。先建立实际镜头视口，再绘制画框内可见身体局部。近景主角须肩部以上、头肩占画面主体；前景角色只可显示后脑/肩/上背局部。禁止把完整全身人物缩小塞进 9:16 画框。SVG 若仍出现完整全身或主角过小，必须重画 SVG、同步修改正文、输出完整修订稿并复检。不得仅加标签或矩形框冒充真实裁切。

### 正式视觉预览门禁（V2.8.7）

火柴人 SVG 只能作为辅助空间图，不得冒充正式镜头预览。用户要求视觉分镜时，优先用已有角色/场景资产合成；无资产则调用可用图像生成能力制作构图样片；有网页低模工具时可用真实相机视口做预览。样片要实际呈现景别裁切、身体朝向、前景遮挡和表情。仅有线框时必须标注“未通过视觉验收”，不可报完成。

## 漫剧资产任务

需要人物、场景、道具或分层视觉资产时，先按《AIGC人物资产指令》建立资产清单和一致性约束，再使用当前实际可用的生成工具制作**独立可用资产**。不得用拼在一张展示图上的资产冒充可直接绑定的独立文件。没有图像工具或无实际成品时，不得声称资产已生成或验收。

## 最终回答

默认优先交付**自检修复后的完整分镜终稿/实际资产**，不以冗长审核报告代替成品。仅在确有未解决问题、缺失素材或未做视频实际测试时，简要标出真实限制。不得把文本复检称为真实视频生成验收。

## 更新顺序

以仓库中三份同名原始指令为唯一权威正文。**先修订并验收原始指令，再核对原文 Git blob SHA，最后同步本技能 references、SKILL.md 和 SOURCE_LOCK.json**。详见 `skills/SKILL_UPDATE_PROTOCOL.md`。不得在源指令未审定前直接修改技能规则。
