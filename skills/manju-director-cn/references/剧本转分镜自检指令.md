# 剧本转分镜自检指令 V2.8.5｜独立质量审核 Skill

> 主指令：[剧本转分镜指令](./剧本转分镜指令)

## 一、两种调用模式

### A. 内部自动自检模式
由《剧本转分镜指令》在初稿完成后调用。必须执行：

检查 → 直接修复 → 复检 → 返回完整修订稿。

不得只给问题清单，不需要用户再次授权改稿。

### B. 独立审核模式
只有用户明确要求“只审核 / 只检查 / 不要改稿”时，才保留原文并输出问题与建议。

如果系统支持独立 Agent / 独立上下文，优先独立审核；不支持时，以独立审稿视角重新核对，不默认相信初稿。



## 二-A、逐阶段文件提交与审核状态审计｜强制项

自检流程必须配合主指令第三十一节的文件化交付门禁。规则加载与项目资料核验默认作为后台门禁记录，不应抢占第一份用户审核产物。每个正式阶段产物均应独立成文件，不能用聊天中的摘要代替完整文件。至少对“带逐镜 SVG 的分镜初稿”、独立审核结果、“同步更新 SVG 的完整修订稿”和最终复检记录分别记录文件名、版本、实际可访问位置、检查状态。

1. **初稿审核**：第一份正式用户产物应是完整分镜文件，并按主指令第九-A节逐镜带 SVG；不得先交规则核验记录替代分镜。核对完整文件，不得仅审查聊天片段、摘要或选定镜头。初稿提交后标记【待用户审核】；不得将初稿自检通过描述成用户已批准。
2. **独立审核文件**：完整记录 P0/P1/P2、对应镜头、可观察证据、最小修复方案和未验证项。独立审核文件自身也必须作为独立产物交付。
3. **修订文件**：修复后输出完整分镜文件，不得只给修改片段；记录修改影响的镜头和关联状态，执行全稿复检。
4. **最终文件与复检记录**：分别交付最终分镜和必要的复检记录；文本审核、程序校验、资产核验、视频实测、用户审核分别记录，不得相互替代。
5. **暂停规则**：用户明确要求逐阶段审核时，提交当前阶段文件后必须停止，等待用户明确反馈，再继续下一阶段。只有用户预先明确授权自动推进，才可免除逐阶段等待；即便如此，也必须保留阶段文件与真实状态。
6. **证据真实性**：文件路径、链接、哈希、创建状态、审核结论和测试结果必须来自实际工具或实际执行；缺少证据时标记【未验证】或【受阻】，不得补写推测性回执。

## 二-B-前置：景别裁切与正背朝向专项否决（V2.8.4）

**对全部镜头逐镜执行，不能只查文字镜头表。**

1. 建立逐镜字段：`主体角色｜文字景别｜实际可见身体边界｜主体占画比例｜前景局部｜身体朝向(正/背/左右侧/前后3/4)｜头部朝向｜视线目标｜摄影机轴线侧｜SVG实际裁切｜检查结论`。缺身体朝向或文字与 SVG 不能判断正背，判 P1；若改变关键动作/互看方向导致因果不成立，判 P0。
2. **严格裁切判断**：本项目人物近景=肩部以上至头顶，特写=头部，中景=腰腹至头顶，全景=全身，远景=全身及环境。若标“近景”但 SVG 展示腰部、腿、完整全身，不论位置多远，必判 P1。若镜中两人均全身出现且主体很小，实际应判双人全景/远景，不许借“近景”名称蒙混。
3. 文字要求“主角近景，另一角色在前景”时，另一角色应为有限肩/头/侧脸局部，而非完整火柴人；主体脸部必须足以呈现文本要求的表情。若想交代站位，额外单独绘空间走位图，而非把整人缩小。
4. 对每个可见人物单独审查身体朝向、头部朝向、视线、相对于摄影机的正背/左右侧/三分之四视角；检查 SVG 是否通过非对称面部特征、肩线、转向箭头或明确标注区分。**圆头+对称四肢火柴人的 SVG 无法验证人物正背，不能打勾通过。**
5. 校验前后镜朝向的起态/终态继承，摄影机反打及轴线保持；不得把视线箭头当作身体朝向证据。
6. 强制反例：文字“天才弟子近景、胸口以上，林拙位于前景”，但 SVG 两人完整全身且主角占画很小，必须返回 P1 并重画近景 SVG、同步修订文字描述/取景边界。修好后**输出全部镜头的完整修订版**，再逐镜复检，不得只给一句“已改近景”。
7. 验收记录必须分别记 `文字景别验证`、`SVG构图验证`、`身体朝向验证`。出现任一未通过不得将该镜标为完成；程序未执行时不能假称自动验证。

### D. 参考图“五档景别”裁切回归门禁（V2.8.5）

将用户提供的同一人物逐级缩框示意视为**构图标准的验收参考**：远景、全景、中景、近景、特写。必须逐镜核验：

1. 远景：全身人物与大量环境；全景：完整全身；中景：腰腹以上；近景：**肩部以上**；特写：头面部或明确局部。不得仅根据分镜文字标签判定景别。
2. 按“**最终 SVG 实际取景画面中的主角最高/最低可见部位**”判定。若画面主角两脚仍在 SVG 中，标“近景”一律 P1；如果该画面关键情绪表演因此不可读或信息任务失败，升级 P0。
3. 人物在场景真实位置和画面裁切彼此独立。为表现远处两人的位置关系而绘制完整小人，只能称全景/远景或额外独立辅助平面图；不可作为肩上近景的 SVG。
4. 9:16 不豁免。画框上下余白不能使人物缩成小点而误称近景；必须实际裁切。
5. 多人镜确定主景别对象和前景局部。对“A近景，B在前景”，应检验 A 肩以上且具有可辨脸部表情、B 仅后脑或肩部局部；不能两个人全身入画。
6. 五档回归必须验证**相机取景逐级收紧**而不是同一全身示意图叠五个标注框。辅助空间图要单独标识，不得冒充正式 SVG。
7. 若出错，先修正文镜头意图、主景别对象、裁切上下限，再同步重画 SVG；**输出整份修订分镜和全部对应 SVG**，逐镜复检，不可只交一幅修正图。

## 二-B、SVG分镜一致性审核｜V2.8.3 强制项

凡正式分镜文件按主指令第九-A节要求带 SVG 时，审核必须逐镜同时检查“文字分镜”和“SVG 示意”，两者视为同一交付物的两个表达层。

1. 每个镜头都必须有独立 SVG；缺失、复用错误或 SVG 无法显示，判 P1。
2. SVG 必须与镜头编号、画幅、人物左右/前后景、朝向、视线、关键空间锚点、道具位置/持有关系和运镜方向一致；一般冲突判 P1，改变剧情事实或关键因果判 P0。
3. 过肩、正反打、越轴、遮挡、镜面/屏幕、手部小道具等高风险镜头必须用 SVG 验证几何关系，不能只检查文字。
4. SVG 只能表达分镜已有事实和必要中性构图，不得新增人物、道具、动作或剧情；新增无来源叙事事实按既有双向覆盖规则处理。
5. 修改文字分镜后必须同步修改对应 SVG；修改 SVG 构图后也必须复查文字、前后镜连续性与状态账本。两者未同步不得放行。
6. 审核记录应明确区分【文字通过/失败】与【SVG一致性通过/失败】；不得因其中一层通过就判整镜通过。


## 二、事实来源与放行前提

审核必须基于：

1. 原剧本或已确认版本。
2. 待审分镜。
3. 已确认人物、场景、服装、道具、品牌和声音要求。
4. 当前目标视频模型的真实能力；若模型上限未知，只能审核剧情和连续性，不能宣称生成分段已最终通过。

没有原剧本时，只能做“分镜内部一致性检查”，不得宣称剧情忠实度通过。

## 三、问题等级统一定义

### P0｜阻断
任一项存在即禁止交付：

- 漏掉、篡改关键剧情、人物关系或原台词。
- 生成段落超过已确认模型真实单次上限。
- 台词/动作明显无法在标注剧情时长内自然完成。
- 在无法稳定恢复的动作、对白、情绪、视线或道具中间状态断段。
- 人物身份、空间、道具归属或关键因果出现物理不可能；明确的容器包含关系被破坏、物体无状态转换瞬移到容器外。
- 必需关键道具/信息缺失。
- 安全或品牌硬规则冲突。
- 生成任务结构无法执行。

### P1｜必修
不属于硬阻断，但交付前必须修复：

- 轴线、视线、人物左右关系错误。
- 左右手、抓握、道具状态或跨镜连续性错误。
- 小幅时长估算不合理但可以通过自然调度修复。
- 关键资产引用不清。
- 服装、场景、光线无依据漂移。
- 冗余空镜、重复镜头。
- 必要生成约束缺失或互相冲突。
- 上下层级关系不清、低层细节覆盖上层空间结构、局部内容与真实遮挡/镜头视线矛盾。

### P2｜优化
不影响正确执行：

- 文字过长。
- 可优化的镜头节奏。
- 无目的但不会造成错误的轻微运镜。
- 可进一步精简的表达。

P0/P1 必须归零才能放行；P2 可在不破坏剧情情况下优化。


## 三-A、V2.8 生成质量主检｜先审“像不像可执行分镜”，再审技术账本

SCG、source_id、关系不变量和程序校验只负责防止世界状态错误，**不能替代导演与生成可执行性判断**。每轮自检必须先回答以下问题；任一关键项失败，即使 SCG 结构正确也不得放行。

### 1. 单镜视觉任务是否明确
每个镜头应只有一个主要观看任务。若同一镜无明确切点却同时要求：
- 两个互斥景别或两个主要焦点；
- 既看清脸部细微表演，又看清画面裁切范围之外的手部操作；
- 多个必须分别看清的关键因果动作；
- 复杂手部操作、关键道具交接、明显走位和复杂运镜同时发生；
判 P1；若导致关键因果无法被观众看懂或实际无法拍摄/生成，判 P0。

### 2. 对白与动作是否争抢生成能力
关键台词镜头优先检查脸、口型、眼神和情绪是否可读。若同时叠加高精度手部、小道具、快速走位、多人抢戏或大幅运镜，要求降级：稳定机位、减少伴随动作、在自然语义点拆镜。不得用异常快语速解决。

### 3. 镜头文本是否真正可拍
逐镜用“摄影机放在哪里、画面看到什么、人物先做什么后做什么、镜头何时结束”复述。若无法形成一条连续可执行的拍摄指令，只是形容词、技术条款或状态清单堆砌，判 P1；关键动作不可执行则 P0。

### 4. 生成段落是否超出复杂度预算
以下高风险项同时叠加时必须主动降级：多人近距离交互、精细手部/小道具、准确文字、镜面/反射、遮挡后显现、群体反应、复杂连续运镜、多个关键切镜、强口型。若段落看似时长合规但生成任务本身明显过载，至少 P1；已知目标模型无法稳定完成仍标“可直接生成”，判 P0。

### 5. 正文是否被后台技术信息污染
正式分镜的【画面】【表演】【运镜】【声音】【后期】【参考素材】【统一生成要求】不得出现 source_id、entity_id、parent_id、SCG、E01-E25、JSON 字段、审核结论和程序日志。出现即 P1，删除技术字段并保留其实际约束含义。

### 6. 审核优先级
固定按：
**剧情忠实 → 可拍/可看懂 → 连续性 → 生成可执行性 → 时长 → 资产/SCG/程序证据 → 电影感**
执行。技术账本通过不能覆盖前面层级的失败。

### 8. 群体人物外观重复专项审核
对买家席、观众席、街道、办公室等多人同框画面，必须独立检查人物外观是否重复：
- 明显相同的脸部、发型与服装组合、身体轮廓，或复制/镜像式重复人物，判 P1；若导致关键角色被复制或身份混淆，判 P0。
- 只写“人物各不相同”不足以通过；应为前景可辨识人物设置少量外观差异锚点，并要求背景群体自然多样。
- 遵循已确认的人物设定和参考素材，不得擅自改变指定角色外观。
- 人群过密时，优先减少清晰可辨识人数并用景深、遮挡和前中后景组织层次；不能只追加负面词。
- 只检查动作复杂度、未检查人物外观重复，属于自检不完整，不得放行。

### 7. 群体镜头微编舞审核
对人群、观众、买家、学生、员工等群体镜头，区分“剧本授权的群体事件”和“模型自行增加的逐人编舞”。
- 3—5 秒短镜头若同时安排多批人物按固定先后顺序完成多个不同动作，且还叠加明显运镜，至少判 P1；
- 群体手部/号牌/小道具已属高风险，再叠加快速横移、摇移或复杂切镜，优先要求稳机位或减动作；
- 同一人物前文已“举起/站起/拿起”，后文又写“继续举牌/继续站起/继续拿起”但没有明确保持还是重复，判 P1；
- 原剧本只授权“群体激烈反应”时，可保留自然错峰和少量锚点人物，不应把每个背景人物都写成独立剧情事件；
- 同一禁止项在多个栏目重复 2 次以上时，要求去重并保留最关键限制。


## 三-B、全类型视觉穿帮专项审核｜与文本/SCG分开判定

逐镜按适用性检查，不得只做格式或 SCG 审核：
- **人物重复**：检查同画面重复脸、相同发型/服装组合、相同身体轮廓、复制/镜像式背景群演。明确人物去重失败至少 P1；关键人物被复制或身份关系受损判 P0。
- **数量与实例**：检查关键人物/道具是否无因新增、消失、复制、替换或瞬移；修复时追踪同一实例，不得靠另造一个对象掩盖状态错误。
- **手部与接触**：检查抓握、手指、道具穿模、悬浮、接触面和左右手一致性；影响关键动作可读性判 P1，导致关键剧情无法成立判 P0。
- **空间与视线**：检查人物座位/走位、轴线、朝向、视线目标和前后景位置；无因换位或镜头关系矛盾判 P1，关键行动方向被颠倒判 P0。
- **跨镜外观连续**：检查脸、发型、服装、伤痕、场景布局、光源方向和关键道具状态；无依据漂移判 P1。
- **动作状态与时长**：检查动作起止、完成后保持/再次执行、人物是否瞬移、多人是否机械同步、时长是否真实可行；影响因果或无法执行判 P0，其余关键穿帮判 P1。
- **屏幕/投影/反射/阴影**：检查内容是否绑定正确载体、原物和光源；错误设备或漂浮内容判 P1，若泄露不应出现的剧情信息则判 P0。
- **声音对应**：检查新增对白、播报、音乐、环境声源和跨镜延续；无来源的新剧情声音判 P1，改变剧情事实或信息披露顺序判 P0。

修复顺序固定为：事实与参考资产 → 实例/空间/状态 → 降低复杂度 → 修订正文 → 前后镜头复检 → 真实样片验收（若样片可用）。必须分别记录文本审核、程序审核、样片审核的状态；未执行的项目标“未验证”，不得推断通过。

## 四-A、参考素材真实性与绑定审核｜新增强制项

逐镜核验【参考素材】是否对应真实可取得的资产，而不是仅出现角色/场景名称。检查资产 ID/路径、版本或确认状态、引用镜头与用途是否清楚；不存在或未实际读取的资产判 P1，并标记【参考未绑定】。如果缺失资产会导致人物身份、场景布局、关键道具或剧情事实无法可靠确定，则升级为 P0/【待确认】。不得虚构参考图内容、资产路径、ID 或已完成的绑定。

跨生成段落声称使用上一段尾帧时，必须确认该尾帧确实已提供或已生成且可访问；否则判定为未绑定，要求明确标记，不得按已完成处理。

## 四-B、逐镜状态账本审核｜新增强制项

对每镜核对“起始状态 → 动作过程 → 结束状态”，至少包括人物身份、左右位置、身体朝向、视线、姿态、左右手、道具持有者/位置/状态、摄影机轴线、服装及伤痕/印记。每镜结束状态必须与下一镜起始状态相容，除非有明确的时间跳跃、场景切换或可见动作完成状态变化。

重点查找隐藏断层：人物从床上突然站到对方面前；手腕仍被抓住却未说明如何操作其他道具；胸针/戒指/手机无来源出现或突然换手；人物在不匹配的景别中执行画外操作；镜面反射、屏幕内外空间关系不一致。仅写“保持连续”不构成通过证据。发现不相容时按 P1 修复；造成物理不可能、关键动作无法续接或剧情因果断裂时判 P0。

## 四-C、对白时长与可执行性证据｜新增强制项

对每段关键对白核算英文词数、可用发声时间及动作/反应占用时间。约 120–180 词/分钟仅作为初筛参考，不得当成所有演员固定语速；若明显超过范围，必须检查是否自然可演。对白与动作挤不进时长，判 P0，重新调度或在语义完整的自然闭合点拆分，不得擅改原文或要求异常加速。

区分“文本审核”“程序校验”“实际视频生成测试”。没有实际执行的程序检查或视频测试不得宣称通过。内部保存问题清单、修复动作、复检结果与仍未解决项；用户要求最终分镜时不必输出冗长审计报告，但证据必须真实存在。

## 四-D、层级继承与容器包含关系审核｜新增强制项

先还原“场景→容器/区域→物体→局部属性”的层级，再逐镜、跨镜和跨生成段落检查：
1. 上层完整写结构、边界和物体归属；下层只补当前镜头新增细节。局部重复重写上层或与上层冲突，判 P1；已经造成空间错误则判 P0。
2. 关键物体必须能回答：属于哪个容器、在哪里、处于什么状态、是否可见、什么动作能改变其位置。
3. 手机在关闭书包内亮屏时，屏幕文字不能无条件清晰可读；“我爱你”属于手机屏幕内容，不是漂浮文字，也不能成为把手机移到包外的理由。
4. 没有打开、伸手、抓稳、移出等完整状态转换时，物体从容器内出现在容器外或同时出现在两处，判 P0。
5. 若屏幕文字必须被观众读到，修复镜头视线、书包开合状态和手机朝向；不得牺牲上层空间约束。

**固定回归案例**
- 书包关闭、手机在包内亮屏：手机不得出现在包外，文字不可读。
- 书包打开、手机仍在包内且屏幕朝向镜头：允许用合理道具特写显示文字。
- 手机被取出：必须有完整连续的取出动作。
- 同一时刻手机既在包内又在桌面：P0，除非有明确取放过程。
- 遮挡未解除却直接读出屏幕文字：P0。
- 局部镜头提示词重写整场布局并冲突：P1；修正低层描述。

## 三-C、V2.8.2 样片失败反推与画面任务削减专项门禁

本节检查《剧本转分镜指令》第一-B节是否真正落实；有相关情形时属于必审项，不新增正式分镜栏位。

1. **必要可见性**：核对每个精细手部/小道具是否剧情必须可见、构图必然入画或运镜会入画。无必要仍强迫在脸部近景显示微小抓握、导致景别/视觉任务竞争，判 P1。剧情明确需要展示的线索不能为降风险擅自移到画外，否则按剧情影响判 P0/P1。
2. **状态继承**：画外道具必须沿用先前唯一实例、持有者、左右手、抓握/佩戴状态；「不入画」不能等同「道具消失或自行换状态」。当前镜重申的局部状态若与上一镜冲突且无动作依据，至少 P1。
3. **运动终帧边界**：对过肩反打、窗框遮挡、人物前景等必须保留的构图锚点，核验运镜起点、方向、终帧边界是否兼容；「轻推近景」导致规定的左肩前景丢失，判 P1，优先减少/取消非必要推进，不以更多禁止词替代。
4. **真实参考绑定**：写「使用起始/结束参考帧」「保持指定人物资产」必须可追溯到真实存在、当前能取得的文件及适用模型功能；未绑定标记【参考未绑定】，不得虚称已验证。静态图片正确也不代表视频全过程正确。
5. **样片与脚本分层**：已有实际生成视频时，检查开头、中间、结尾及首次错误点，并分别核验关键道具接触、空间/前景锚点、实际时长、台词完整性、音画同步和无来源音乐。文本、校验器、视频样片的结论分开记；尚未做的检测必须写「未验证」。
6. **最小修复与回归**：失败先定位根因类别，选择缩减非必要可见内容、调整景别、固定机位、绑定正确参考帧、模型支持的控制选项或局部重生成；禁止只复制叠加通用否定词。修复后复查关联前后镜头，保存期望/实际结果。

**固定回归案例：镜头05（Evan左肩过肩反打）**
- 输入：Evan左后方机位；Evan仅左肩/少量左后脑在虚化前景；Alessandra坐在桌对面北侧红色高背椅；黑曜石戒指由右手拇指与食指捏持而非佩戴；7秒英文对白镜头；原方案含微推进。
- 若戒指并非当前近景必须可见：正文保留其持握连续状态、让右手处于自然画外，不将戒指作为额外可见任务；若必须可见：改为实际可看清正确抓握的合理构图/必要镜头，并绑定有效参考。
- 若推进将使Evan左肩退出画面：取消或减弱非必要推进，保留过肩空间锚点，不以单人特写替代。
- 样片中出现戒指佩戴、前景消失、机位错位、英文台词缺失或时长不符时，视频验收失败；不能因为提示词列出禁止事项而放行。
- 自动测试应分别判断：剧情事实是否未删、近景可见性是否相容、非必要推进是否降级、终帧锚点是否明确、道具状态是否从前镜继承、样片审核是否独立标注。未取得新视频不得标为「视频实测通过」。

## 四、审核顺序｜不得跳步

### 1. 原剧本覆盖审核
内部建立逐场映射：每个关键事件、原台词、人物、情绪转折、关键动作和道具是否都有对应镜头。

检查遗漏、杜撰、顺序改变和因果错误。

### 2. 生成段落定义审核
逐段确认：

- 生成段落是否真的代表“一次 AI 视频生成任务”。
- 是否误把整场戏直接当一个生成段落。
- 是否误把每次镜头切换都当成新生成任务。
- 一个段落可包含多个镜头，只要连续性与生成复杂度合理。

### 3. 时长精确审核
解析每个段落时间码：

剧情实际时长 = 结束时间－开始时间。

逐项核对：

- 标注时长是否计算正确。
- 单段实际时长是否 ≤ 模型真实上限。
- 10秒上限不得出现10.1秒；15秒上限不得出现15.1秒。
- 是否为了凑10秒/15秒增加空镜、重复动作、停顿或拖慢对白。
- 固定生成档位是否与剧情实际时长被错误混淆。

超上限为 P0。

### 4. 连续剧情与分段边界审核
先判断当前切点是不是必要。

如果一个连续事件能在模型上限内自然完成且复杂度合理，默认不拆。

重点检查是否切在：

- 抬手、抓握、递交、开合、起身、坐下、转身、跨门等中间态。
- 半句对白或未完成语义中。
- 视线、表情、情绪尚未稳定时。
- 因果事件尚未完成时。
- 道具状态难以在下一段准确复现时。

出现上述高风险断点判 P0，优先合并或换自然闭合点。

长台词超过单段上限时，只能在语义完整分句、标点停顿或自然呼吸点拆分，原文不得漏词、重复或改写。

### 5. 跨段恢复审核
逐段核对上一段尾帧→下一段首帧：

- 人物身份、站位、朝向、视线。
- 身体姿态和左右手。
- 道具位置、状态、持有者。
- 场景结构、光线、服装。
- 情绪和声音延续。

跨段延续却没有上一段尾帧/连续性参考，或下一段起始状态描述不足，判 P1；如果因此无法可靠恢复关键动作，升级为 P0。

### 6. 镜头与摄影审核
检查：

- 景别与实际裁切一致。
- 人物特写=仅头部；近景=肩至头顶；中景=腰腹至头顶；全景=全身；远景=人物+环境。
- 摄影机机位、轴线、视线和正反打正确。
- 关键动作期间没有无目的复杂运镜。
- 一个镜头有明确视觉重点。

### 7. 动作与道具审核
核对起始状态→过程→结束状态。

重点检查：

- 左右手分工。
- 接触/受力。
- 抓握。
- 交接。
- 打开/关闭。
- 拿取/放置。
- 道具是否凭空出现/消失/换手/换状态。

### 8. 声音与后期审核
检查：

- 原台词完整、顺序正确。
- 自然语速与镜头时长匹配。
- 未擅加背景音乐、旁白、笑声或无关音效。
- 剧本明确的字幕/屏幕/合同文字等是否放入【后期】而不是错误要求视频模型生成。
- 后期文字必须准确，不得由模型随机生成错误文字。

### 9. 人物、资产与画面稳定性
检查人物身份、脸型、发型、服装、体型和场景结构是否与已确认资产一致。

检查人物复制、肢体畸形、多余手指、穿模、瞬移、闪烁、融化、无故变焦、旋转、场景混合等风险是否有必要约束。

### 10. 冗余镜头审核
逐镜问：

“删除这个镜头后，会不会损害剧情理解、必要空间关系、关键线索、时间变化、情绪落点或转场？”

如果不会，且没有新增信息，判 P1，删除或合并。

不得为了凑模型时长保留空镜。

### 11. 输出结构审核
每个生成段落必须有：

- 段落头。
- 一个或多个镜头的【画面】【表演】【运镜】【声音】。
- 必要时的【后期】。
- 【参考素材】。
- 【统一生成要求】。

不得把内部审核账本塞进最终分镜。除非主指令规定的 Handoff 条件实际成立，否则最终正文也不附加 SCG；即使启用 Handoff，也必须与分镜正文完全分隔。

### 10-A. 剧情压缩与关键因果保留专项审核

逐镜检查“叙事价值是否配得上实际时长”，不能只检查有没有空镜：

1. **时长与信息量匹配**：镜头是否只是无对白的功能性交代，却用了多个镜头、慢推、凝视、等待或重复动作拉长时间？若删除停顿或合并镜头后剧情仍清楚，应压缩。
2. **最短可理解时长**：询问“观众理解本镜新增信息，实际需要看到多久？”按动作复杂度和情绪价值核算，不按模型档位平均分配，也不把参考秒数当硬指标。
3. **最小因果链完整**：压缩后是否仍保留必要起始状态、关键动作/接触、完成结果及其因果？缺一项且导致剧情不成立，判 P0；只是表达冗长但不影响因果，判 P1。
4. **关键接触未被偷掉**：拾取、交接、插入、拔出、开锁、按键启动等若影响剧情，必须至少让观众看清动作确实成立。仅展示“动作前”和“结果后”，却没有可辨认的接触/状态转换，判 P0。
5. **不得过度拆镜**：同一连续功能动作是否被机械拆成多个独立特写？若单一稳定构图即可表达，合并；只有视野冲突或生成风险确有必要时才拆。
6. **不得为了压缩破坏可生成性**：若短时长内包含过多精细手部操作、遮挡和道具变化，检查是否应简化构图/动作并行关系。不能只写“迅速完成”掩盖执行困难。
7. **无信息增量的内容**：没有剧情来源、情绪变化、空间必要性或新信息的空镜/停顿/重复反应应删除，不因“电影感”保留。

修复时先保住原剧本事实和关键因果，再压缩准备、等待、重复与镜头数量；修改后重算时长，并从头复检前后镜头状态。禁止为了压缩删台词、篡改剧情或令动作无法辨认。

## 五、自动修复顺序

内部自动自检模式按以下顺序修：

1. 先修原剧本遗漏/篡改。
2. 再修生成段落定义和硬上限。
3. 再修连续剧情断点和跨段恢复。
4. 再修台词/动作时长。
5. 再修空间、轴线、动作、道具连续性。
6. 再删冗余空镜。
7. 最后精简提示词和生成约束。

修复后重新从第1项开始复检。

如果连续两轮复检仍出现同一个 P0/P1，停止无效循环，标记【受阻】并给出具体原因，不得伪称通过。

## 六、输出规则

### 内部自动自检模式
返回**完整修订后的最终分镜脚本**，不是审核报告。

只有仍存在无法自主解决的【待确认 / 受阻】事项时，在终稿末尾简短说明受影响镜头和原因。

### 独立审核模式
可以输出：

- 检查范围。
- P0/P1/P2 数量。
- 具体镜头/段落问题。
- 最小修复建议。
- 最终判定【通过 / 待修复 / 受阻】。

## 七、最终放行条件

只有同时满足以下条件才可判定“分镜脚本审核通过”：

1. 原剧本关键内容覆盖完整。
2. P0=0，P1=0。
3. 每个生成段落定义正确。
4. 每段时长计算正确且不超过模型真实上限。
5. 没有为凑模型档位增加内容。
6. 连续剧情没有不必要中断。
7. 必须拆分的位置都有稳定可恢复的边界。
8. 台词和动作在对应时长内自然可完成。
9. 人物、空间、道具、声音连续，且层级/容器/遮挡可见性一致。
10. 冗余空镜已删除，功能镜头时长与叙事价值匹配，且关键因果动作未被压断。
11. 最终格式可直接用于下游生成。
12. 层级继承、容器包含关系、物体位置转换和屏幕内容可见性通过回归案例。

“脚本审核通过”只代表分镜脚本通过，不代表视频已经生成或成片质量通过。


## 八、V2.8 独立审核补充门禁（覆盖原有同类检查，不降低原规则严格度）

### 8.1 双向覆盖
构造 source_id → shot_id 与 shot_id → source_id 两张映射。前者检查漏项，后者检查无来源的叙事事实；不允许仅凭“关键情节大致出现”通过。剧情关键事实冲突判 P0；非关键过度创作判 P1。

### 8.2 可见性五重判定
检查被拍物体是否同时满足：镜头视锥、无不透明遮挡、足够画面尺寸、内容朝向可读、光照/曝光可辨。区分物理存在、角色感知、观众可见、观众可读四种状态；未满足条件却明确展示剧情关键内容判 P0。

### 8.3 时间区间与动作先后
逐镜核验台词、动作、反应、运镜的时间区间及前置依赖。允许自然并行动作，不得机械相加；必须串行的动作若重叠矛盾或超过时长判 P0。时间码缺失或不连贯判 P1，影响模型上限判 P0。

### 8.4 导演表现与观众信息
逐场检查戏剧目标、障碍、转折、情绪曲线；逐镜检查视觉重点、信息增量、观看顺序与情绪反应。发现机械罗列、关键揭示提前、反应镜头误删或没有可拍的视觉重点，依关键因果影响判 P0/P1。导演表现不能只以华丽运镜计分。

### 8.5 空间图与景别可见性
依据固定人物坐标核对动作轴线、摄影机所在侧、视线匹配、银幕左右；跨轴须有空间重新建立的证据。依据本项目自定义景别裁切核对实际可见部位。动作发生在裁切区外却要求观众直接看清，判 P1；造成核心因果不可见判 P0。

### 8.6 生成风险与降级
逐段检查人物互动、手部精细动作、文字准确性、反射、遮挡、切镜、口型、参考图绑定及目标模型能力。风险过高必须提出不篡改剧情的可执行降级手段；对明确不能生成却标为可执行判 P0。后期精确文字必须写明制作责任，不得默认模型能生成准确字符。

### 8.7 结构化程序校验与证据记录
对稳定 ID、引用完整、时间码计算、父容器一致、事件转移、段落上限、台词顺序执行实际程序校验。记录校验器版本、输入版本、执行结果、异常列表。未运行时只允许写“待程序验证”，不得标记通过。生成视频测试与审稿测试必须独立记录。

### 8.8 修复影响与全局复检
任何修复都要记录 issue_id、严重度、影响镜头、修改点、关联 source_id、前后状态差异与复测结论。镜头/道具/时长变更后重算关联段落与后续镜头，不能只重查本镜。再次出现同一 P0/P1 时标记阻断，避免以无效循环掩盖未解决问题。

### 8.9 固定回归样本
至少测试：手机在关闭书包内亮屏但文字不可见；包内手机经打开书包后可见；无动作瞬移到包外；单个物体同时出现两处；握腕导致手部冲突；动作途中跨生成段落；长对白自然语义拆分；近景错误显示画外手；未经重建的越轴；修改前镜头时间导致后镜时间错乱。对每个案例保存期望判定、实际判定与修复结果。

### 8.10 审核结果分层
区分【脚本逻辑通过】【结构化校验通过】【资产核验通过】【视频生成实测通过】【成片复核通过】。不可把前一层等同于后一层。最终放行仍以 P0=0、P1=0 为硬条件，并明确所有未开展的验证项目。


## 九、叙事来源与人物/群体行为审核｜强制项

### 9.1 行为来源核对
逐项审查对白、动作、表情、群体反应、道具操作、环境变化、音效与事件结果，建立 source_id → shot_id 和 shot_id → source_id 双向映射。每项内容必须属于【剧本明确】【必要因果】【中性调度】之一。无法归类或没有依据的新增事件不得放行；不得以“导演发挥”掩盖剧情增写。

### 9.2 鼓掌与群体反应固定门禁
剧本没有明确写掌声时，不得因为发言结束、演讲成功、会议场景、角色获胜或存在观众而添加鼓掌。欢呼、哄笑、惊呼、起立、点头、哭泣、嘘声、集体沉默等同样适用。剧本明确只有某些人反应时，不得扩写成所有人。若群体反应改变场景气氛、人物立场或剧情含义，擅自新增判 P0；其他无来源的可见人物行为至少判 P1。修复时删除无来源反应，恢复剧本要求的中性现场状态，不得再添加另一种猜测性反应替代。

### 9.3 反应主体、触发时点与范围
凡剧本明确要求的群体行为，必须确认谁做、由什么事件触发、何时开始、持续多久、哪些人参与。若来源只写“有人鼓掌”，不能推断所有人；若写“观众鼓掌”，不得自动让台上人物、工作人员或反对者一起鼓掌。主体范围会改变剧情含义而原文不清时，标记【待确认】。

## 十、场景锚点与物体实例唯一性审核

逐镜核对场景中已有的椅子、桌子、门、床、书包、手机、吊瓶架、杯子及其他关键物体是否保持同一 object_id。已存在实例可完成当前动作时必须复用，不得无来源新增第二个实例或用新物体替代旧物体。核验物体位置、朝向、占用、开合和持有状态是否从前镜继承；物体被遮挡/出画不等于消失。场景确有多个同类实例时，按空间位置和场景参考绑定正确实例。

### 固定回归：单把椅子
- 场景参考明确只有一把椅子A，角色要坐下：必须坐椅子A。
- 角色扶椅背或踢开椅子：动作必须作用于椅子A。
- 椅子A移动后下一镜：继承新位置；不得同时保留旧位置的椅子A并再生成椅子B。
- 只有原剧本明确新增/搬入另一把椅子时，才允许创建新实例并记录来源。

## 十一、结构层级与物理动作因果审核

涉及吊针/输液装置、穿刺、胶带、软管、衣物、容器、机械连接等对象时，检查整体与部件、内部与外部、表面固定与外露连接、实际抓握对象和连接方向。每个关键动作核对“动作前状态→主体→接触对象→运动过程→中间状态→结果→后续状态”。例如拔针场景必须以实际参考为准区分进入皮肤的部分、表面胶带、外露部件和软管；若剧本要求拔出后流血，应表现足以成立的拔出过程及伤口结果，不能让胶带进入皮肤、让装置无因消失，也不能只出现无因流血。不得添加剧本未要求的伤势程度。

## 十二、固定回归测试扩充

每次独立自检必须至少判定以下案例的预期结果与实际结果：
1. 剧本未写掌声，发言结束：不得添加掌声。
2. 剧本写“部分观众鼓掌”：不得扩展成全场所有人鼓掌。
3. 剧本明确全场鼓掌：只在指定触发点开始，不提前、不让无关角色自动加入。
4. 场景只有椅子A：角色坐、扶、踢均使用椅子A，不新增椅子B。
5. 手机位于关闭书包内：不可无动作出现在包外，屏幕文字不可无依据可读。
6. 拔吊针：内部/表面/外露部件关系、实际抓握对象和流血因果成立。
7. 物体被遮挡或离开画面：不代表删除或复制。
8. 修复任一前镜：复查所有受影响后续镜头、群体行为和物体状态。
对每项保存【预期判定、实际判定、修复动作、复检结果】。只写“已检查”而没有逐项结果，不算通过。

9. 单镜无切点同时要求头部特写与腰下手部操作：必须拆镜或改景别，不能两者同时成立。
10. 关键对白同时叠加精细手部操作、道具交接和大幅运镜：必须降级或在自然语义点拆镜。
11. SCG/关系图全部合法但镜头只是规则清单、没有明确视觉重点：不得判通过。
12. 分镜正文出现 source_id/entity_id/SCG/E01-E25 等后台字段：删除技术污染后复检。
13. 4 秒“买家疯狂举牌”却拆成前排三人依次举牌、后排分批加入、多人前倾/抬头、最终高潮并同时快速横移：过度微编舞，必须压缩为群体趋势 + 少量锚点动作，并优先稳定机位。
14. 已写“每名买家完成一次举牌”，后文又写“继续举牌”：状态含糊，必须改为“举起后保持”或明确第二次举牌的来源与动作。
15. 买家席/观众席出现重复脸、相同发型服装组合或复制式群演：判人物外观去重失败，修复后复检。


## 十三、SCG 时空场景约束图审核｜先审关系再审文字

独立审核时不得只逐句看分镜文本。先从原剧本、场景资产和分镜还原 Scene Constraint Graph，再检查每个镜头是否只是合法地呈现/更新同一张图。

### 13.1 持久实例
跨镜检查 entity_id 是否保持唯一。物体出画、遮挡、反打、切近景后仍应保持同一实例；无来源 duplicate、delete、replace 判 P1，若影响关键剧情/因果判 P0。

### 13.2 关系持续与合法变化
逐镜比较 inside、part_of、attached_to、mounted_on、held_by、sitting_on、projected_onto、displayed_on、reflected_in、casts_shadow_on 等关系。关系变化必须有 source_id 对应的触发动作。没有触发事件而发生 parent 改变、容器脱离、物体复制、表面内容脱离，判 P0/P1。

### 13.3 父子继承
父对象移动时检查仍连接的子对象是否随父对象更新；子对象若留在原世界位置，必须有明确脱离动作。容器移动而内部道具留在原处、墙移动/镜头重建导致附着物漂离等均不通过。

## 十四、视觉介质类型审核｜投影/屏幕/反射/阴影/表面标记

逐项先判定介质类型，再审核其约束：

- surface_projection：必须有 source 和 receiver_surface，内容贴合接收面，不得悬浮。
- screen_content：必须位于对应 screen surface，关屏后不可继续存在。
- reflection：绑定 reflective_surface，不创建第二人物/物体实例。
- shadow：绑定光源、遮挡物和接收面，不是实体。
- surface_mark：绑定具体表面，不得无动作脱离。
- volumetric/hologram：只有剧本明确要求才允许自由悬浮。

### 固定回归：墙面投影
预期：投影仪A开启 → projection_effect P1 projected_onto 墙面W1；P1 与墙面方向/透视一致；相机移动仅改变画面投影透视，不改变 P1 的接收面。
错误：
1. P1 出现在墙前空气中形成独立矩形屏幕。
2. 墙面仍有 P1，同时空中又复制一个 P2。
3. 相机横移时 P1 跟随相机移动。
4. 投影仪关闭后 P1 仍存在。
5. 未经剧情允许从 wall W1 改投人物或另一面墙。
剧情核心受影响判 P0，否则至少 P1。

## 十五、接触、支撑、部件和载体一致性审核

检查 object/part/surface 的结构关系，尤其是人体操作、小物件、家具、门窗、机械部件、穿刺物、胶带、软管、衣物、饰品和表面信息：
- part 不得无依据脱离 parent。
- resting_on/sitting_on 必须有对应支撑物实例。
- held_by/grasping 必须与手部位置和可见性相容。
- attached_to/taped_to/mounted_on 必须保持接触，除非有解除动作。
- projected_onto/displayed_on/written_on 等信息不得被误生成为独立实体。
- 遮挡只改变 visibility，不改变 existence。
- 相机切换只改变观察方式，不自动改变世界状态。

## 十六、失败模式矩阵与放行门禁扩展

最终放行前至少逐项检查：
1. 实例复制/消失/替换。
2. 父子层级断裂。
3. 容器包含错误。
4. 部件—整体错误。
5. 支撑/接触悬空或穿模。
6. 表面附着漂移。
7. 投影/屏幕/反射/阴影介质错型。
8. 遮挡与可见性混淆。
9. 相机运动误改世界状态。
10. 动作缺前置条件或结果无因。
11. 群体行为无来源或主体范围扩张。
12. 道具持有者/左右手漂移。
13. 数量漂移。
14. 场景锚点漂移。
15. 时间切换后错误继承或错误清空。

每项必须记录【通过 / P0 / P1 / 不适用】及对应镜头。存在任何未解决 P0/P1，不得标记脚本审核通过。


## 十七、V2.8 层级只读继承审核

逐镜判断当前描述属于 L0-L6 哪一层，并检查低层是否越权重写高层。重点查：
- 镜头层是否重新定义整场布局；
- 局部描述是否改变已有家具数量；
- 为展示细节是否移动容器内物体；
- 为方便构图是否改变父子/附着/接收面关系；
- 风格描述是否意外引入新对象或新剧情。
低层覆盖高层事实，至少 P1；造成物理/剧情错误判 P0。

## 十八、资产权威级别审核

逐项确认 A0/A1 资产是否被正确复用。若已有椅子、手机、桌子、投影幕、门、床、吊瓶架等实例可满足当前动作，却重新生成同类替代物，判 P1；若造成数量漂移、空间断裂、剧情误读，判 P0。

禁止把资产图中的表面内容误识别为独立对象，例如：
- 墙面投影 → 悬浮屏。
- 屏幕文字 → 空中文字。
- 镜中倒影 → 第二个人。
- 阴影 → 黑色实体。
- 墙上图案/海报 → 脱离墙面的物体。

## 十九、载体锁审核

对所有 phenomenon/information 节点检查 carrier_id/receiver_id：
- 若 receiver 不变，内容不得漂浮或改投。
- 若 carrier 被关闭/移除，依赖内容应相应消失或失效。
- 相机移动不得修改 projected_onto/displayed_on/reflected_in 关系。
- 只有原剧本明确全息/悬浮时，才允许独立世界坐标。

出现未授权的 surface-bound → floating 转换，剧情核心受影响判 P0，否则 P1。

## 二十、人物行为来源审核

对每个可见人物动作建立 actor_id、source_id、trigger_event。群体行为逐项核对参与者范围。
固定失败样例：
- 发言结束但剧本未写掌声 → 不得鼓掌。
- 一人鼓掌 → 不得自动全场鼓掌。
- 只写“几个人鼓掌” → 不得扩展到所有人。
- 角色获胜 → 不得自动欢呼。
- 发生冲突 → 不得自动让所有围观者惊呼。
- 原剧本未定义态度 → 不得擅自增加赞同/嘲讽/敌意。

## 二十一、关系不变量自动复核

每镜结束后对下一镜重新比对：
- entity_id
- parent_id
- quantity
- holder
- inside/attached/mounted/projected/displayed/reflected
- support relation
- crowd scope
- visibility vs existence

只有显式事件允许变化。无事件变化即记为非法跳变，并追溯到最早发生的镜头，不只修当前镜头。


## 二十二、程序化 SCG 审核门禁｜V2.8

独立审核除了文字复核，还必须检查是否存在可执行的 SCG 校验证据。

若环境支持 Node.js：
- 读取 [分镜SCG数据契约-V1.md](./分镜SCG数据契约-V1.md)；
- 使用 [分镜SCG校验器-V1.js](./分镜SCG校验器-V1.js)；
- 对待审场景的结构化状态实际执行校验；
- 保存退出码、错误码、对应镜头和修复后复检结果。

固定回归样例 [分镜SCG回归样例-V1.json](./分镜SCG回归样例-V1.json) 必须保持全量通过后，校验器结果才可作为放行证据。

当前 V1 校验器不是完整物理引擎，也尚未覆盖错误矩阵全部 E01-E25。退出码 0 只能表述为【SCG V1 已实现规则通过】，不能表述为“全部空间/物理/连续性已自动验证”。

如果没有 SCG 数据、没有实际运行校验器或运行失败：
- 不得标记【结构化校验通过】；
- 只能继续文字审核并标记【SCG程序校验未执行/失败】；
- 若缺失会影响关键道具、容器、载体、人物行为或动作因果，则不能最终放行。

### 22.1 审核顺序更新
正式顺序改为：
原剧本事实覆盖 → 资产绑定 → SCG 世界初始化 → 事件/状态转换 → SCG 程序校验 → 分镜正文核对 → 独立自检 → 必要修复 → SCG 再跑 → 最终复检。

任何修复如果改变实体、parent、关系、数量、持有者、容器、投影接收面或群体行为范围，必须重新运行 SCG 校验，而不是只看修改后的文字是否顺眼。


## 二十三、学员纯对话 SCG、场景资产优先与集末状态审计｜V2.8

### 23.1 不得把工具当作学员前提
学员可能没有仓库、MCP、文件访问或代码执行能力。审核规则必须在纯对话模式下也可执行：
- 能运行程序时，检查真实校验器输出与回归结果；
- 不能运行时，执行结构化的逐项模型审核，并明确标记“模型规则审核；SCG程序校验未执行”；
- 禁止伪造脚本运行、程序 PASS 或机器检测证据。

### 23.2 检查是否过度登记场景背景
默认将场景资产视为固定环境和普通家具的权威来源。不要要求每一把背景椅子、每张桌子、每盏灯都独立登记。
检查以下情况是否正确：
- 剧情交互对象已从场景资产中绑定为既有实例，而不是重新生成；
- 只有接触、移动、使用、损坏、承担剧情信息或需要跨镜精确保持的对象才提升为独立 SCG 实体；
- 场景缺少必要道具时，是否明确标记为待制作/待确认资产，并在批准后稳定复用；
- 固定场景布局是否被无授权改变；
- 背景补充是否意外新增关键道具、改变数量或制造重复对象。

### 23.3 生命周期和切场清理审计
检查每个被追踪实体的作用域是否合理：
- persistent：跨场/跨集剧情事实；
- character_bound：人物穿戴/携带物；
- scene_local：只在本场景需要精确追踪的实体/状态；
- shot_local：短时临时现象。

场景切换后：
- 普通固定家具由场景资产管理，不应无意义地进入下一场/集状态表；
- scene_local 退出活动账本不等于世界中被销毁，不得误报为物理删除；
- 角色携带物、穿戴物、关键线索、伤口、服装连续性和未完成事件不得被场景清理误删；
- 若后续返回旧场景，恢复权威场景资产，并只恢复会影响剧情的持久变化；
- 被遮挡/出画不是销毁；场景切换也不是自动销毁，必须区分“退出追踪作用域”和“剧情世界中删除”。

### 23.4 Handoff SCG 按需输出审计
先判断本次任务是否真的启用了 Handoff。只有以下情况之一成立时，才要求最终交付独立的 `【AI内部连续性状态｜SCG｜非分镜正文】`：
- 用户明确要求跨集/跨会话连续性状态；
- 当前任务明确会继续下一集且需要交接；
- 下游系统明确需要状态附件；
- 存在必须跨集持续、仅靠正文容易丢失的关键状态。

**未满足上述条件时，不得因为格式惯性强制在每集末尾输出 SCG。** 内部可以继续维护轻量状态，但最终只交付分镜正文。

启用 Handoff 后检查：
1. 正文与 SCG 明确分隔；
2. 附录只保存下一集有用的跨集状态，不罗列所有背景桌椅；
3. 角色状态、关键携带物、关键道具位置/持有者、人物知识状态、未完成事件与下一集硬约束完整；
4. 普通场景家具与结束的临时现象已从交接状态清理；
5. SCG 内容不得被解释成画面、字幕、旁白或视频生成内容。

### 23.5 复核优先级
先核对原剧本和已确认资产，再核对 SCG 与事件；随后检查分镜正文；最后检查集末交接状态。若 SCG 与正文冲突，定位最早冲突镜头并修复，不得通过增加重复道具或无来源事件来掩盖问题。
