# Skills 更新治理协议（指令源优先）

版本：1.0.0
适用：本仓库所有 `skills/*` 技能包。

## 强制顺序

1. **先确定权威指令源**：从 `AGENTS.md` 路由到对应原始指令，确认当前 main 分支文件、版本、Git blob SHA。
2. **先修订指令源**：如果用户要求的规则尚未完整、存在冲突、过时或验收缺口，先修改权威指令文件。禁止先改 SKILL.md 再反向修改原文来迁就技能。
3. **指令验收**：逐项检查目标、适用范围、工具/权限边界、工作步骤、依赖、验收标准、失败处理、交付格式；对冲突作出明确决定。需要代码或案例的规则，应运行对应测试。
4. **冻结本轮指令基线**：确认源文件版本与 blob SHA，并生成本轮 SOURCE_LOCK 清单。没有通过源指令验收，不进入技能包更新。
5. **更新 Skills**：把验收后的指令原文放入对应 `references/`，再更新 `SKILL.md` 的触发条件、引用路径、工作流和验收契约。不得仅保留链接、摘要或依赖在线抓取。
6. **内容一致性验证**：对照 SOURCE_LOCK 核验源 SHA、字符数/文件大小及规则标记；确认技能引用的所有文件都存在，且没有把过期版本冒充最新版。
7. **技能包测试**：验证目录结构、YAML frontmatter、文件引用路径、必需规则锚点和压缩包内容。存在可执行测试时运行测试并记录真实结果。
8. **最后发布**：仅在上述检查通过后提交 Skills 更新。技能包版本递增并更新 README、SOURCE_LOCK；保留可追溯来源。
9. **失败处理**：任何源指令验收失败，停止本轮技能发布，报告具体失败项；不得通过只改 SKILL.md 绕过问题。
10. **对外说明**：区分“源指令已审定”“Skill 文件已更新”“技能包结构已验证”“目标平台已安装/运行验证”。不能将前几项冒充最后一项。

## 禁止事项

- 不得先更新技能再补改指令源。
- 不得声称 GitHub 更新会自动更新用户已经下载/安装的本地技能快照。
- 不得声称 ZIP 上传后模型一定自动解压并读取全部文件。
- 不得把生成了文件、提交成功或静态检查通过说成真实平台端到端验收。
- 不得覆盖与当前任务无关的现有技能文件；更新时仅修改本次明确范围内的文件。
