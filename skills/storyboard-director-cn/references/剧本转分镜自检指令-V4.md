# 剧本转分镜独立验收门禁 V4.0

> 本规则与仓库基础《剧本转分镜自检指令》联合执行。V4.0 是在原有 source/SCG/资产/连续性检查之上的新增门禁，不删减旧规则。没有实际工具或证据的项目必须标“未执行”，不能用推断填成 PASS。

## 门禁顺序

### G0｜来源、权限与剧本忠实度（P0）
- 源剧本版本明确；镜头/对白/人物/道具/动作有来源映射。
- 原对白逐字核对；未经授权没有新添关键人物、死亡、能力、事实、因果或结局。
- 原剧本和分镜的冲突先列明，不通过擅改原文“修复逻辑”。
- 角色资产、场景、道具、模型能力引用真实存在；未找到则标待确认，不编造资源 ID。

### G1｜戏剧价值与观众认知（P0/P1）
- 每场明确人物目标、阻碍、策略变化、代价、信息揭示与场尾状态。
- 观众看到的信息与角色当时知道的信息一致；反转有铺垫，谜底有可追溯证据。
- 关键事件可从画面/声音识别，而非仅靠旁白或分镜备注宣称。
- 无叙事作用且不承担节奏/转场价值的镜头应合并或删除。
- 情绪峰值必须有触发原因、不可逆选择和可观察反应；“悲伤/震惊/燃”标签不算证据。

### G2｜动作物理、时间和并行事件（P0）
- 所有镜头区间连续、无未解释空档/重叠，且处于集总时长内。
- 核心事件的 start/end 与可见镜头对应；关键事件 requires_visible 不得无证据。
- 检查前置依赖、持续动作起点、角色/手部/独占道具的占用区间。
- 同一人物的互斥复杂动作不得重叠；合法并行必须说明原因。
- 连续 N 秒操作从实际接合/受力开始计时；准备、格挡或其他动作不能偷算入持续时间。
- 群像区分“实际发生人数”与“逐个可见人数”；若时长不足，必须重新导演呈现方案。
- 对白按台词字数、角色语速、停顿和音频时长复核；身体动作以实测优先。估算不能标实测。
- 运行分镜事件时长校验器 V4 和 V4 回归样例；只有工具实际运行且退出码为 0，才可记程序校验 PASS。运行失败/无法执行要保留错误并标未执行。

### G3｜空间、机位与镜头连续性（P0/P1）
- 角色屏幕方向、轴线、入画/出画、视线、距离、摄影机方位可衔接。
- 关键道具在拿起/放下/交接后状态正确；不能瞬移、复制、无来源出现或消失。
- 每镜至少明确主要视觉焦点；动作关键接触点不能被遮挡或只用光效盖掉。
- 运镜服务于揭示、压迫、跟随、方向感或情绪，不以运镜名称替代实际路径。
- 切镜动机明确，下一镜能接住动作、声音、视线、情绪余波或信息揭示。

### G4｜战斗可读性（适用于有战斗的作品；否则 N/A）
- 有明确战术目标、起手/攻击线、守方选择、接触结果、反制、局势变化和代价。
- 特效没有遮盖主要攻击方向、命中点、受力与后果。
- 重复招式必须带来新的位置/资源/伤情/知识/策略变化；否则属于视觉重复。
- 人物能力符合剧本世界规则；战斗结果不是只靠无因果闪光宣布。

### G5｜情绪、节奏与音画（P1）
- 关键情绪有铺垫、触发、选择、他人反应与余波；牺牲看得见代价。
- 强度有变化，动作后果能被观众辨认；不以固定秒数强行切镜或强制每场反转。
- 对白、呼吸、效果声、环境声和音乐有明确层次；若生成模型不支持相应音频，标为后期需求。
- 不将“导演风格名称/电影感/高级感”当成质量证明。

### G6｜动态证据（P0，按交付类型适用）
- 逐镜 SVG 只证明静态构图意图，不证明动作连贯。
- 用户要白模预演时，实际检查运镜、走位、关键接触、事件起止与切镜；不要求无表情白模通过表情验收。
- 用户要视频/成片时，需对实际生成文件进行抽帧或播放检查；没有生成文件不能写视频测试通过。
- 无法访问相关工具时继续完成其他可做项，并明确受阻层级；不虚构结果。

### G7｜交付与版本（P0）
- 完整稿可读取，镜号、时码、对白、图示、资产引用和状态账本互相一致。
- 自动模式：完成文字稿、自检、修复、复检后一次交付。逐阶段模式：初稿交付后暂停等待用户审核，不能越过用户关卡。
- 记录 V4 规则版本、原剧本版本、修订版本、程序测试证据和未验证事项。
- 旧版离线 ZIP/技能快照不能标为最新版；只有 SOURCE_LOCK 与正文 SHA 已更新并实际重打包，才可宣称同步。
- 交付前核对文件真实存在、能打开、版本与链接一致，并按用户指定路径备份（权限允许时）。

## 严重度与修复
- P0 阻断：剧情事实/关键因果错误；关键事件无法发生或不可理解；时间互斥；持续时长不成立；核心道具/人物状态错误；必需交付缺失或虚构验收证据。
- P1 必须修复：战斗重复且无局势变化；情绪峰值无铺垫/代价；视觉焦点混乱；无效镜头显著拖慢节奏；空间/切镜可读性差。
- P2 优化：不影响理解和连续性的美术、运镜、节奏细节。
- 默认放行要求 P0=0、P1=0；P2 可列为可选改进。对每个 P0/P1 指明镜号、证据、根因、上下游影响和最低成本修复，再修复整稿并重新跑所有相关检查。

## 回归样例（不可只口头承诺）
1. 13人逐一过门3秒 + 轮椅搬运 → 必须识别展示负载冲突。
2. 连续压闸30秒，但前8秒仍在战斗/安装机关 → 持续起点冲突。
3. 人物同时执行两项互斥复杂动作 → 排他区间冲突。
4. 关键事件在正文有描述、但没有镜头可见证据 → 事件覆盖失败。
5. 镜头时码有空档/重叠或超出集总时长 → 时间结构失败。
6. 合法并行事件（例如一人说话、另一人同时观察）必须允许通过，不能把所有重叠一概判错。
7. 估算动作时长未实测 → 可作为设计预估，但不得报告 measured/PASS 视频验收。


## V4.0 与基础自检规则联合执行
本文件是 V4 增量门禁，必须与仓库根目录《剧本转分镜自检指令》联合使用；根规则中的全部 source、SCG、状态、资产与回归门禁仍然有效。只有文本审核完成不代表程序校验或实际视频验收通过。 
## V4 发布前比较验收门禁（不可跳过）
正式合并到 main 前，必须用同一份《病友仙门：炼气守星》V3.2 74镜脚本和生产账本，分别按 V2.10.1 基线与 V4 规则进行对照审核。至少记录：
1. V2.10.1 已通过但 V4 新发现的问题，附镜号和源文证据；
2. V4 的误报/不必要拆镜/无效加字段，验证是否破坏用户可读性；
3. 关键动作与持续事件的时间冲突是否被发现；
4. 剧本事实、对白、资产/SCG/状态规则是否无回归；
5. 静态构图、白模/动态预演、真实视频各自的实际状态。
目前已从文本和生产账本确认 S065-S067 的30秒持续压闸时长不成立，S068 的13人逐一核牌/登船/轮椅过舱门在3秒内需要导演重新设计或实测，S056 的稳息与触剑顺序存在可并行/串行歧义，必须标为 NEEDS_REVIEW 而不能凭假设硬判。
只有完成全量74镜文本对照、结构化时间测试和真实预演证据后，才能将候选合并到 main。缺真实预演时，PR 保持 Draft/Open，不能通过发布门禁。


## V4.1-RC1 独立质检增量：AI镜头执行与Take证据
> 对应同分支导演 V4.1 增量章节；这是候选门禁，不代表真实视频已通过验收。原有基础自检、G0-G7、SCG、事件时间和74镜发布门禁继续有效。

### Q1｜导演稿→模型编译完整性（P0/P1）
- 每个生产GEN对应真实 scene_id / shot_ids / gen_id / source_id，绑定权威资产版本、首帧、期望尾态、镜头起止构图、运动主体和时间拍点；缺少必需字段标 UNVERIFIABLE，不以补造字段蒙混。
- 摄影运动检查类别是否准确：景别≠运镜；推轨≠变焦，摇摄≠横移。存在两个以上主运动而无模型支持证据须降级/拆镜，不允许凭“电影感”放行。
- 模型版本、模式和参考能力有可追溯官方或实测证据，未知能力不能写已支持。

### Q2｜双人近景及越轴（P0/P1）
- 检查人物左/右ID、前后遮挡、视线目标、焦点角色、摄影轴线侧以及镜头进出状态的连续性。
- 人物换位、合法反打、越轴过渡与非法跳轴分别判断；不允许将所有左右交换一律判错，也不允许镜头换轴默许资产交换。
- 不可用的轴线、动作状态、资产引用字段应记 UNVERIFIABLE，不得零告警就报告 PASS。

### Q3｜仙侠打斗与阵法物理层级（P0/P1）
- 每个关键击打必须看见或可靠剪辑交代攻击向量、接触/有效闪避、受力方向与终态；如果未接触却宣称命中，标P0。
- 施法者、锚定面、阵纹次序、能量路径、受影响目标与消散规则应继承SCG世界状态。
- 地面阵纹/后景/角色法器/碰撞能量/前景粒子/后期合成层次合理，决定胜负的接触点不得被粒子掩盖。

### Q4｜独立Take审片与失败恢复（P0）
- 输出唯一任务/GEN/Take ID，记录生成模式、模型版本、素材和参数hash、真实时长、可用in/out、实际尾态、镜头运动偏差以及失败首时刻。
- 不允许将目标首尾帧描述当成实际Take首尾状态；下一GEN必须引用真实合格Take。
- 失败需归因身份漂移、空间轴线、接触点、时长、特效遮挡或模型能力，并留最低成本的改拍方案；有副作用提交须先核对任务状态，禁止盲目重复生成。

### Q5｜程序三态及分层证据（P0）
- 仅在实际运行的SCG、事件时间和镜头专项程序均无错误且关键字段齐全时，才可给出对应的程序级PASS。明确违规为FAIL，字段或程序证据缺失为UNVERIFIABLE（不可放行）。
- T文字、P白模、K关键帧、V视频、E成片分别记录证据文件、执行者、时间、结果；T或程序PASS不得替代V/E。
- 研究目录的独立检查器及其静态回归只是候选参考实现；未集成到实际生产流水线时必须记“镜头专项未执行”，不可虚称系统已经生效。
- 设计师言炎原作12镜头尚无逐帧取证，不允许将行业通用技巧标成其原话或已复现经验。

### V4.1回归附加案例
1. 双人近景字段不完整 → UNVERIFIABLE。
2. 未授权的越轴、资产身份互换 → FAIL；经真实建立镜头/反打记录的合法变化 → 允许通过。
3. 模型模式没有复合运镜证据却要求多主运动 → FAIL/降级。
4. 打击缺接触/受力终态或特效遮蔽接触点 → FAIL。
5. Take存在且尾态不符下一镜预设 → FAIL；缺少真实Take → V层未验证。
6. 所有静态规则通过、但未进行视频生成 → 只允许相应静态层PASS。

### 出具审查报告
逐条给出“镜号/GEN ID/问题类别/证据/严重度/最低成本修复/上下游影响/重测结果”；不得只报总分。发布前保留原有74镜对照和动态预演门禁，禁止仅因本文件更新就合并main。
