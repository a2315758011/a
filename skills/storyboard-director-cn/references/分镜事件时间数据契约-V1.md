# 分镜事件时间数据契约 V1

## 用途与边界

本契约补充主线 V2.10.1 的 SCG 与镜头约束，不替代它们。SCG 负责实体、关系、事件来源与状态传递；本校验器专门检查结构化时间轴、事件持续时间、前置依赖、互斥动作和持续操作起点。

输入必须是从已确认分镜中提取并经人工复核的 JSON 事件账本。它**不会自动理解普通中文分镜稿**，也不证明生成视频真的执行了这些动作。

## 最小结构

```json
{
  "episodes": [
    {
      "episode_id": "EP01",
      "time_start_ms": 0,
      "time_end_ms": 10000,
      "shots": [
        {
          "id": "S001",
          "time_start_ms": 0,
          "time_end_ms": 5000,
          "visible_event_ids": ["E001"]
        }
      ],
      "events": [
        {
          "event_id": "E001",
          "actor_ids": ["CHAR_A"],
          "event_start_ms": 1000,
          "event_end_ms": 3000,
          "requires_visible": true,
          "exclusive": true,
          "duration_status": "measured",
          "min_duration_ms": 700
        }
      ]
    }
  ]
}
```

## 字段规则

- 时间统一使用毫秒。推荐使用全片连续的全局时间轴；每集的起止时间、镜头起止时间和事件起止时间必须使用同一时间基准。
- `episode_id`、镜头 `id`、`event_id` 必须稳定且不重复。校验器兼容旧候选字段 `id/start_ms/end_ms`，但新数据优先使用 `time_start_ms/time_end_ms` 与 `event_start_ms/event_end_ms`。
- `visible_event_ids` 只记录观众在对应镜头中确实能看见的事件；不能因为事件在世界状态账本里出现，就自动算作画面证据。
- `requires` 列出必须先完成的事件 ID。只有导演已明确动作先后关系时才建立依赖；原文无法判断串行还是并行时，标记 `NEEDS_REVIEW`，不可让机器猜测。
- `actor_ids`、`exclusive`、`exclusive_resources` 描述同一人物或独占道具/机关是否可并行执行。可并行动作必须有明确依据，不能用“动作同时发生”掩盖身体互斥。
- `continuous_hold: true` 表示持续操作；若需要先完成机关接合，使用 `engagement_event_id` 指向接合事件。持续操作不得早于接合完成。
- `duration_status` 为 `measured` 或 `hard_constraint` 时，低于 `min_duration_ms` 可报硬错误；估算阈值只能产生警告并进入 `NEEDS_REVIEW`，不得冒充真人实测。
- `presentation: "sequential_visible"` 表示逐人逐项可见；`shown_count` 与 `min_per_person_ms` 只能在有实测或明确硬约束时判硬失败。改为蒙太奇或群像锚点必须明确说明它是省略展示，不等于每个人都被逐一展示。
- 结构化数据缺失、动作先后含糊或实测数据不足时，标记待审核；不得编造生理最低时长或把估算当事实。

## 执行与验收

在技能目录执行：

```bash
node scripts/分镜事件时长校验器-V1.js tests/分镜事件时长回归样例-V1.json
```

退出码 0 表示测试样例与预期结果一致，不表示所有输入分镜通过。若某个负例按预期被识别，单个用例会显示 `pass: true`、`ok: false`；这代表检测器正确发现缺陷，而不是分镜合格。

本工具只验结构化时间账本。最终仍须执行文本独立审核；只有目标模型、资产和真实视频可用时，才能进行关键帧、动态预演和生成视频验收。
