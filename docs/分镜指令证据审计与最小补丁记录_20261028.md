## 2. 四类清单

### 已有能力（保留，不重复建设）
1. 导演推演：视觉节拍、观众信息、镜头新增信息、情绪的可见化、动作链与镜头功能检查。
2. 空间/连续性：人物世界坐标与摄影机取景分离；身体/头部朝向与视线分开；道具状态必须由事件驱动；跨镜起止状态衔接。
3. 独立审核与修复：P0/P1/P2、最早冲突点修复、前后关联镜头复检、完整稿重出。
4. SCG 实体/关系/事件状态程序校验，及专项穿帮样例。
5. SVG 非必交付规则，防止内部示意图污染正式分镜正文。

### 规则冲突 / 执行冲突
1. 主线 SCG 的 time_* 字段不能单独证明已做时间事件校验；旧 SCG 校验器不负责事件时长、串并行依赖、机关接合时序。
2. Skill 与离线规则包必须按 SOURCE_LOCK 校验版本；只改调度入口而不更新来源锁会产生“文档写了新校验器，但安装包无法追溯真实来源”的风险。
3. PR #17 的强制在线双规则门禁与 Skill 的离线快照工作方式并不等价；应先决定产品究竟采用在线强门禁还是可审计的离线快照，不应把两种模式混写成同一个成功状态。
4. “逐人展示”与“蒙太奇/群像锚点”是不同的呈现合同，不能用估算时长硬阈值冒充真实实测。

### 有证据的缺陷
1. 真实候选案例：PR #19 记录 S065–S067 的持续压闸 30 秒与动作起点冲突；S068 的 13 人逐一核牌/登船挤在 3 秒内；S056 稳息与触剑的串行/并行语义未明确。该 PR 同时注明 74 镜事件账本未全部建立，故这三项是已报告缺陷，26 个启发式候选只是待复核项。
2. 本次程序复现：事件时间校验器对 JSON 数组中的 null shot / null event 缺乏完整的防御性处理。新增 null-shot、null-event、null-event-with-peer 回归并补充对象类型守卫，避免坏输入导致异常或不完整检查。
3. 结构化时间检查不能从普通中文分镜自动推断事件；必须由人工/AI先提取并复核账本。缺少账本不等于镜头通过。

### 待验证假设
1. 结构化事件时长校验能否减少真实生成中的动作缺失/时序冲突，需要同一完整剧本基线的 V2.10.1 与候选规则对照。
2. 关键帧约束、生成后诊断与定向修复能否提高跨镜一致性，需要固定模型、资产、参数、随机种子/可比设置和独立盲审。
3. 横店 AI 服务平台采购需求能否转化为该仓库的具体验收项，必须以原始招标文件全文为准；本次公开公告页面列出了 DOCX 附件，但第三方网页对需求正文有遮蔽，未取得并核读该 DOCX 全文，因此不把媒体概述当成正式采购条款。

## 3. 证据与方法

### 研究原文
- Better Call CineCrew（arXiv:2609.07720）：https://arxiv.org/abs/2609.07720
  - 提出 FilmDSL 结构化中间层、资产包/故事板关键帧、逐段生成、结构化 QA 与定向修复。它支持“将镜头约束结构化并形成生成—批评—修复闭环”的设计方向；论文实验不能直接证明本仓库提示词有效。
- CamPilot（arXiv:2609.10943）：https://arxiv.org/abs/2609.10943
  - 研究摄影机规划、镜头运动/构图与跨镜关系，并提出 CamEval 评测。可作为摄影机规划和可量化评估的研究证据，不应宣称它已是生产级通用工具。
- Generative AI for Film Creation（arXiv:2504.08296）：https://arxiv.org/abs/2504.08296
  - 综述人物一致性、风格一致性、动作连续性、细粒度控制等问题；属于综述而非本仓库效果的直接实验。
- 横店影视 AI 服务平台公开招标公告（2026-09-14，列出“发布稿--横店影视AI服务平台建设项目.docx”附件）：https://www.qianlima.com/bid-630934780.html
  - 页面确认项目与招标文件入口，但正文部分遮蔽；本次未把未读附件内容作为证据。
- 独立公共采购交叉参照：政府采购网《东阳市AI+影视生态服务项目》公告（2025-11-07）：https://www.ccgp.gov.cn/cggg/dfgg/gkzb/202511/t20251107_25656881.htm
