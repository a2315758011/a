# AI 通用操作复用库

目标：避免 AI 对同一件事重复思考、反复手工点击、重复编写相同代码。

## 强制操作顺序
1. 连接工作站并读取既有 .infra/AGENT_PROTOCOL.md、ENDPOINTS.json、PROJECT_REGISTRY.json。
2. 先检索：`node 复用管理器.js find 关键词`。
3. 找到匹配后查看技能：`node 复用管理器.js show 技能ID`，检查适用范围与参数。
4. 执行：`node 复用管理器.js run 技能ID --arg 参数`；每次自动追加到执行记录.jsonl。
5. 验证结果，脚本失败时记录真实原因，禁止未经检查反复提交有副作用的操作。
6. 无脚本且同一流程预计复用超过 3 次：做成参数化脚本，添加索引、验收、失败恢复说明并实际测试。
7. 操作本来只需一次且脚本化不划算，则直接执行，不机械增加脚本。
8. 多 Agent 写入遵守资源锁；不要覆盖既有脚本，修改前备份并做回归测试。

## 使用
在本目录运行：
- `node 复用管理器.js list`
- `node 复用管理器.js find 恢复`
- `node 复用管理器.js show project-bootstrap`
- `node 复用管理器.js check`
- `node 复用管理器.js run project-bootstrap --arg win-unpacked`
- `node 复用管理器.js run file-inventory --arg C:\路径`

## 速度与可靠性
缓存的是已验证的操作过程和标准参数，而不是盲目重放鼠标坐标。优先使用现有 API、CLI、Playwright 或程序入口；GUI 只作为必要的回退方式。未登录、页面未就绪、窗口变化或任务已经提交时必须先检查状态，不允许盲目重试。

## 安全边界
默认只读。修改系统设置、批量覆盖文件、删除内容、部署及涉及账号操作须单独审核并遵守现行权限和资源锁。不得在本库明文保存密钥、令牌或 Cookie。执行管理器仅支持库内 JS/PS1 文件，未索引的脚本不得直接自动运行。

## 现状
已内置只读项目恢复与目录扫描两个示例技能。具体业务自动化需逐个验证后收录，不能仅靠目录存在就宣称业务完成。
