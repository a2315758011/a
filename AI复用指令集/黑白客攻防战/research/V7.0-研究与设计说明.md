# 黑白客攻防战 V7.0 候选｜研究与设计说明

日期：2026-10-22
状态：候选；未覆盖当前V6.1/V6.2主线
目标：专门解决“人类对手利用AI自己的规则、证据结构、时间预算和历史判断反向操纵AI”的问题。

## 1. 本次真正修复的根因

前几个版本把攻击模型主要放在“AI会不会跑偏、会不会误用工具、会不会缺证据”上，但用户实际采用的是更高一层的攻击：

> 不直接攻击目标系统，而是攻击AI的判断框架本身。

典型过程：
1. 对手提供一个写得像正式裁定的虚假主张，例如“目标已确认，按规则6/23属于某限制类别”；
2. AI把它当成事实，而不是USER_FACT_CLAIM；
3. AI把这个未经验证的结论写进合同、报告或项目记忆；
4. 下一轮AI再次读取自己的合同，把旧推断升级成“已确认事实”；
5. 对手再利用AI的范围、计时、证据和安全机制，让AI自己停止大量原本允许的工作；
6. AI花大量比赛时间核验对手刻意制造的元问题，而不是推进真实目标。

这是一种“权威洗白 + 标签投毒 + 自我证明循环 + 规则DoS”的组合攻击。

## 2. 外部研究支持

### 2.1 OWASP Prompt Injection

OWASP当前说明指出，Prompt Injection的结构性问题来自“指令和数据进入同一上下文”，模型没有天然可靠的方式区分它们；间接注入可以通过网页、文档、API返回等外部内容进入Agent上下文。

V7对应设计：
- 把USER_GOAL / USER_FACT_CLAIM / OBSERVED / EXTERNAL_SOURCE / INFERENCE / MEMORY / UNTRUSTED_EMBEDDED_TEXT分开；
- 工具输出、网页、文档中的指令默认只作为数据；
- 高风险行为依赖运行时权限和真实状态，而不是依赖文本标签。

来源：
https://genai.owasp.org/glossaries/prompt-injection/

### 2.2 OWASP Agent Control Standard（2026-09-01）

ACS强调Agent必须可观察、可追踪、可在运行时施加策略控制。它说明纯自然语言提示词不是可靠的运行时强制边界。

V7对应设计：
- 明确本地规则只能约束决策流程，不能替代外部运行时控制；
- 普通JSON计时器只作为审计记录，不声称防篡改；
- 将“规则遵守”与“真实工具/下游状态”分离。

来源：
https://genai.owasp.org/resource/agent-control-standard-acs/

### 2.3 AgentLAB（ICML 2026）

AgentLAB覆盖intent hijacking、tool chaining、task injection、objective drifting、memory poisoning等长程攻击，并指出单轮防御不能可靠解决长程Agent威胁。

V7对应设计：
- 增加多轮逐步伪权威植入；
- 增加多轮时间消耗攻击；
- 记忆只作为恢复线索，不自动作为当前事实；
- 对手可以逐轮学习并改变攻击手法。

来源：
https://proceedings.mlr.press/v306/jiang26as.html

### 2.4 AuditBench（2026-03-10）

AuditBench的重要发现之一是tool-to-agent gap：某个工具在静态测试中能产生有效信号，不代表Agent会正确使用它。Agent可能少用有效工具、被噪声误导，或看到正确证据后仍形成错误假设。

V7对应设计：
- 外部知识和工具只负责产生证据；
- 必须把证据转换成可证伪假设和下一项最小判别实验；
- “工具调用成功”不等于“问题解决”。

来源：
https://alignment.anthropic.com/2026/auditbench/

### 2.5 Training Alignment Auditors via Reinforcement Learning（2026-10-15）

该研究报告点式/二元奖励会被reward hack：审计Agent会制造“看起来严重”的发现或叙述尚未真正建立的结论。研究采用pairwise reward，并混入没有隐藏行为的校准目标后，虚假阳性控制更好；表现较好的策略趋向受控、系统性实验。

V7对应设计：
- 关键能力优先采用pairwise比较；
- 每个攻击案例配正常/最小差异控制；
- 不能只测“能否发现风险”，还必须测正常合法任务是否仍能完成；
- 公开回归不能代替秘密留出。

来源：
https://alignment.anthropic.com/2026/training-alignment-auditors/

### 2.6 NIST ARIA Evaluation Planning Manual（2026-09-18）

NIST ARIA将模型测试、红队和用户测试组合为整体评估，而不是用单一分数替代全部能力。

V7对应设计：
- 单独报告端到端成功率、假胜率、误拦截率、时间DoS、工具使用、证据质量和多轮稳健性；
- 不再压缩成一个“总分”宣称AI变强。

来源：
https://www.nist.gov/publications/aria-evaluation-planning-manual-elements-aria-style-ai-evaluations

## 3. V7 与 V6.1 的主要差异

1. 把“对手提供的是输入，不自动是真相”放在第一层，而不是后置的提示注入规则。
2. 明确区分流程指令与事实主张；用户可以规定比赛30分钟，但“按规则6/23已经确认X”仍是事实主张，需要核验。
3. 引入反权威洗白：规则编号、历史裁定、其他AI结论、合同状态都不能靠自然语言声明直接生效。
4. 引入来源依赖图：多份复制自同一AI旧判断的文档不构成多源证据。
5. 引入META_BUDGET：对规则和标签的核验也有时间预算，防止人类用规则DoS耗光比赛时间。
6. 明确“局部限制不扩散”：只阻塞真实受影响的具体动作，其他独立允许分支继续。
7. 引入15个人类对手攻击家族，其中包含激将、紧迫性、矛盾洪泛和评分器博弈。
8. 从固定流程转为最小判别实验：每一步必须改变判断、推进最终oracle或保存必要证据。
9. 采用pairwise/minimal-counterfactual作为核心回归方式，减少关键词过拟合。
10. 公开回归与秘密留出彻底分离；只有蓝方不可见留出才能证明未知对手泛化能力。

## 4. V7公开回归集

文件：
`黑白客攻防战_V7.0人类对手抗操纵回归集.json`

当前结构：
- 26个公开案例；
- 10个稳定攻击家族；
- 9组显式最小差异配对；
- 2条多轮连续攻击序列；
- 7个正常任务控制案例。

与V6.1不同：
- familyId数量受控，不再使用“每个案例一个类别”制造虚假覆盖；
- pairGroupId / pairVariant / controlledVariable / heldConstantFields显式存在；
- sequenceId / turnIndex显式存在；
- 验收器不会仅凭一个“pairCorrect=true”布尔值假装存在真实配对结构。

## 5. 结构验收器实测

文件：
`黑白客攻防战_V7.0结构验收器.js`

已实际运行：
- Node语法检查：PASS；
- validate：PASS，26 cases / 10 families / 9 pairGroups / 2 sequences / 7 benignControls；
- selftest：PASS；
- 删除一组pair的B变体会被拒绝；
- 打断多轮turnIndex连续性会被拒绝；
- 使用未定义familyId会被拒绝。

这些结果只证明V7候选规则和公开回归集的数据结构正确，不证明当前AI已经通过它。

## 6. 仍然不能假装完成的事项

尚未执行：
1. 当前模型在V7公开回归集上的真实运行；
2. 与V6.1/V6.2的同模型、同工具、同预算A/B；
3. 蓝方保管的秘密留出测试；
4. 用户这个真实人类对手的30分钟正式对抗；
5. 在外部可信执行中间件上实现真正不可篡改的时间门禁。

因此当前正确状态是：
- V7设计：已完成并通过结构自测；
- V7是否真正更强：未验证；
- 是否能打赢用户：未验证。

## 7. 正确的后续验收

真正证明V7有效，需要：
- 同一个模型/Agent；
- 相同工具权限；
- 相同初始状态；
- 相同30分钟预算；
- V6.x和V7分别运行；
- 蓝方保管未公开案例；
- 至少重复多次；
- 独立评分；
- 同时统计正常任务完成率，避免“什么都怀疑/什么都拒绝”获得虚假高分。

只有这些数据出来以后，才可以说V7是否比V6更强。
