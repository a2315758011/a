# RECOVERY-024｜结算面板接入与验收契约

项目：live-turret-defense  
引擎：Cocos Creator 3.8.2  
当前阶段：只做候选 UI 资产与接入契约；等待用户美术签收后才允许进入正式主场景 / Prefab。

## 1. 已知现状

- V5 美术方向：严格 90° 正交俯视、手工像素风、深石/苔地、青色守护水晶、三种差异化炮塔、绿色兽人、克制的黄铜/熔岩点缀。
- UI 方向：深炭灰石材/枪铁、暗海军蓝内板、少量黄铜边缘、青色能量高光；中文标签和数字由 Cocos Label 绘制，不烘焙进图片。
- 当前控制器已有 ready / running / paused / win / lose 状态；已有“重开”操作，但尚无独立的结算弹窗或真正的主菜单状态。
- RECOVERY-023 已用真实鼠标完成自然失败、完整水晶收缩、失败灰化和重开闭环；JS 错误 0。候选 UI 不得改变战斗胜负计算。

## 2. 资产契约

- 结算面板底板只包含一个完整 4:5 竖向框体；无文字、数字、图标、按钮、Logo 或水印。
- 外部背景用纯色键色，仅供导出阶段去背；最终 SpriteFrame 必须是透明 PNG。只去除背景色，不得误删青色高光、黄铜边缘或暗色内板。
- 保持像素边缘清晰，禁止模糊、抗锯齿光晕、渐变噪点和过度装饰；在 360px 宽屏仍可辨认。
- 候选资产必须使用独立新增目录；不覆盖 V4/V5 已有资产。生成母图、去背后的 PNG、尺寸/Alpha 检查结果、哈希与来源任务 ID 一并归档。
- 中文文案和按钮始终为独立 Cocos 层，不能嵌入底板图片。

## 3. 建议结算信息

在 win / lose 状态刚发生时冻结一份只读结算快照，至少包含：

- 结果：守城成功 / 水晶失守
- 波次：当前波次 / 总波次
- 击杀数
- 水晶剩余耐久 / 最大耐久
- 结算时炮塔数量
- 本局游戏时长

仅显示真实状态中已有的数据；观众人数、礼物价值、奖励货币和历史最高纪录若没有真实数据源，不得编造或显示假数字。快照只用于显示，不可回写战斗数据。

## 4. 交互约束

- 弹窗只在 win / lose 显示；其他状态隐藏。
- 失败时优先让水晶死亡收缩动画完成（约 0.7–0.9 秒）后再弹出结算面板，避免面板遮挡关键反馈。
- 弹窗打开后必须阻断下层战场输入，不能误触“开始”“升级”“离场”或镜头控件。
- “再战一次”必须调用真实重开流程；鼠标与触摸合成事件只执行一次。
- 当前还没有真正的主菜单状态。“返回主界面”在主菜单状态与入口完成前不得接成空操作，也不得偷偷映射为重开；首版可只提供一个真实可用的“再战一次”按钮。
- 胜利与失败两种终态都必须有独立视觉状态；不可只改标题文字而不验证面板布局。

## 5. 响应式布局

- 使用 view.getVisibleSize() 和安全区布局，不使用固定的 540×960 绝对坐标作为唯一方案。
- 面板建议宽度 min(320, visibleWidth - 24)，高度按 4:5 比例计算；确保 540×760、360×780、393×852、540×960、540×1108 五种视口中不裁切。
- 标题、数据行和按钮保持足够点击高度；不遮挡系统安全区。弹窗可对背景加暗化遮罩，但不能模糊像素画面。

## 6. 接入后的强制验收

1. Cocos Creator 3.8.2 构建成功；确认 build success、TS 错误 0、入口存在，退出码接受 0 或官方成功码 36。
2. 五种视口逐一真实鼠标/模拟触摸：结算显示、内容不溢出、按钮可点、下层输入被拦截。
3. 自然失败路径：HP 到 0 → 水晶收缩完整 → 失败结算显示 → 再战一次 → ready / HP100 / 9 塔 / 0 击杀 / 0 敌人。
4. 胜利路径：三波通关 → 胜利结算显示 → 统计与实际游戏状态一致 → 再战一次恢复初始值。
5. 重复点击/鼠标+触摸合成输入不会重开两次；控制台 JS 异常 0；既有缩放、拖动、回中、观众加塔、升级、离场回归不退化。
6. 在用户签收美术之前，只验候选资产和隔离候选场景；不得替换正式守城主场景或正式 Prefab。
